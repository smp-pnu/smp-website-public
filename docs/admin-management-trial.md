# 관리자 콘텐츠 관리 시험판

운영 사이트와 Notion의 게시 경로는 그대로 유지한다. 이 브랜치의 승인·정렬·삭제는 독립 관리자 Worker와 독립 D1에만 반영된다. 운영용 원본 Drive를 삭제하거나 Notion 글을 수정하지 않는다.

## 사용자 작업

- **찾기:** 학기 보관함 → 팀/업종 → 기업명·종목코드·제목·파일명 검색. 20개씩 표시한다. 검색과 필터는 이미 받은 메타데이터 안에서 처리하며 타이핑마다 서버를 호출하지 않는다.
- **순서:** ‘직접 정한 순서’에서 손잡이 드래그 또는 위·아래 화살표. 서버에 전체 순서를 저장한다. 새 파일은 앞에 추가하며 기존 항목 간 순서를 유지한다. 필터 상태에서 옮겨도 전체 순서에 반영된다. 운영 사이트 목록과는 아직 연결하지 않는다.
- **AI 보완:** 기본값은 꺼져 있다. 목록·편집 화면에서 선택하고 PDF 앞 3쪽의 전송 미리보기를 확인한 경우에만 Cloudflare AI를 호출한다. 전화번호·이메일 패턴은 제거하지만 이름·주소까지 익명화를 보장하지 않는다. 건너뛰면 기기 내 기본 추출만 사용한다.
- **등록/수정:** PDF 등록 후 기업·제목 등 후보를 검토하고 저장한다. 시험 승인에는 필수값 검증과 원문 확인이 필요하다.
- **일괄 처리:** 현재 페이지에서 최대 5개 선택 → 학기/작성자·팀/업종 변경 또는 휴지통 이동. 휴지통에서 일괄 복원/영구 삭제한다. 여러 창의 수정 충돌 시 전체 작업을 중단한다.
- **PDF 교체:** 편집 화면의 ‘PDF 교체’. 같은 원본은 그대로 재사용한다. 새 원본과 표지를 모두 저장·검증한 뒤 원래 글 ID에 연결한다. 제목·분류·순서를 유지하고 승인을 해제한다. 기존 근거는 지우며 새 원문 확인 또는 후보 다시 추출이 필요하다. 전송 실패/취소/수정 충돌 시 기존 파일을 보존한다.
- **공지:** 공지 작성 → 제목/날짜/분류/상단 고정 → 본문, 소제목, 글머리·번호 항목, 인용, 구분선, 사진 → 미리보기 → 변경 저장 → 시험 승인. 내용 단위의 화살표로 사진과 문단을 재배치한다. 링크는 https/mailto만 허용하며 HTML은 실행하지 않는다.
- **사진:** JPEG/PNG/WebP를 기기에서 긴 변 1600px 이하·1MiB 이하 정적 WebP/JPEG로 재인코딩한다. 공지 1개당 사진 12개, 본문 12,000자/80개 내용 단위. 원본 이미지 메타데이터를 복사하지 않는다.

## 보관 및 용량

Drive 연결 전에는 PDF·표지·공지 사진을 **시험 D1**에 저장한다. 새 Drive 연결, 불변 승인본, 파일 격리 보관의 최신 절차는 [Drive 저장 시험 안내](admin-drive-trial.md)를 따른다. 운영 Drive 이관과 공개 전환은 아직 하지 않는다.

- Drive 연결 전 리포트 최대 50개, 연결 후 500개. 공지 최대 100개. 휴지통도 한도에 포함한다.
- PDF/표지/공지 사진/전송 중 파일을 합쳐 원시 바이트 기준 200MiB. 서버 SQL에서 한도를 확인한다. 파일 교체 중에는 이전·새 파일의 임시 공간이 모두 필요하다.
- PDF당 32MiB, 120쪽. 분할 업로드와 최대 2회 연결 재시도를 유지한다. 교체 완료 응답이 유실되어도 완료 영수증으로 같은 결과를 반환한다.
- 본문 타이핑 자동 저장/상시 폴링/Cron은 추가하지 않는다. AI 호출은 기존 하루 10회·동일 원문 캐시 정책을 유지하며 PDF 교체 자체는 AI를 호출하지 않는다.
- 휴지통은 30일 뒤 다음 관리자 접속 또는 목록 조회 때 정리한다. 청소는 최대 시간당 한 번이다.
- 중단된 PDF 업로드는 30분, 저장하지 않은 공지 사진은 24시간 뒤 다음 청소 때 제거한다. 본문에서 제거한 사진도 24시간 유예한다. 저장된 본문이 참조하는 사진은 만료하지 않는다.
- 리포트 영구 삭제 시 파일은 별도 기록으로 30일 격리하며, 다른 승인본/글에서 참조하지 않을 때만 정리한다. 공지 영구 삭제는 기존처럼 사진을 함께 제거한다. 관련 AI 후보 캐시는 비운다.
- 수정·삭제·교체는 버전 번호로 충돌을 검사한다. `guardedBatch`의 CHECK 가드와 D1 트랜잭션이 동시 변경 시 전체를 롤백한다.

## 모듈과 검증

- `admin-lab/library-model.ts`: 필터·정렬·이동의 순수 함수.
- `admin-cloud/library.ts`: 서버 순서, 일괄 수정/삭제.
- `admin-cloud/store.ts`: 원본 저장, 완전성 검사, 원자적 파일 교체, 청소·공유 용량.
- `admin-cloud/notices.ts`: 공지 검증, CRUD, 사진 소유 관계.
- `admin-lab/notice-editor.tsx`, `notice-preview.tsx`, `notices.tsx`: 작성/안전한 렌더링/목록 및 작업 흐름.

`pnpm test`, `pnpm typecheck`, `node tests/admin-cms-render.mjs`, `pnpm test:admin:cloud`, `pnpm build:admin:cloud`로 검증한다. Cloud runtime 테스트는 실제 workerd와 로컬 D1에서 인증·청크 업로드·바이트 일치·순서·일괄 수정·파일 교체·공지 CRUD·사진 정리를 확인한다. 실제 브라우저 확인은 이와 별개다.

스키마는 추가 테이블·이력 한도 트리거를 도입한다. Drive 원본을 등록한 뒤에는 Drive 지원 이전 Worker로 단순 롤백하지 않는다. 콘텐츠 복구가 필요하면 먼저 삭제를 멈추고 별도 백업/검증을 진행한다. 운영 데이터베이스에 시험 스키마를 적용하거나 운영 배포 명령을 실행하지 않는다.
