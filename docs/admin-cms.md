# 관리자 CMS 운영

2026-10-27부터 콘텐츠 관리의 기준은 별도 관리자 화면이다. Notion 원본은 이관 기록과 복구 자료로 보존하며, 이후 Notion 변경은 공개 사이트에 반영하지 않는다. 기존 글 주소와 사이트 디자인은 유지한다.

## 담당자 사용법

- **리포트:** 리포트 등록 → PDF 선택 → 자동 추출된 기업명·종목코드·제목 확인 → 검토 완료 · 게시 초안 만들기 → 게시. 새 PDF의 표지와 전체 페이지 준비가 끝나야 공개된다. 작업은 보통 15분 이내 시작하지만 파일 크기·대기열·플랫폼 상태에 따라 더 걸릴 수 있다. 준비 중 안내는 글을 다시 열어도 유지되며, 실패 상태에서 게시를 재시도할 수 있다. 기존 공개본은 유지된다.
- **수정·교체:** 제목 등의 수정은 초안 저장 후 게시한다. PDF 교체도 기존 글에서 시작해 같은 주소를 유지한다. 입력 후보는 반드시 원문과 대조한다.
- **순서:** 리포트와 공지 목록의 손잡이를 파란 삽입선에 놓는다. 위·아래 버튼도 지원한다. 공개된 글의 순서는 바로 반영된다. 검색·학기 필터로 대상을 찾을 수 있다.
- **공지:** 공지 작성 → 제목·게시일·본문 편집 → 미리보기 → 초안 저장 → 게시. 사진, 제목, 목록, 강조, 인용, 표, 첨부를 지원한다. 사진은 브라우저에서 크기를 줄이며 PDF·ZIP 첨부는 개당 1.4 MB 이하이다. 원본 Notion 서식 중 지원하지 않는 새 블록을 자동 변환하는 기능은 없다.
- **회원:** 기수·구분·이름·학과·학번 표시·직책·사진을 수정하고 게시한다. 같은 기수에서는 회장, 부회장, 기장, 가나다순이다.
- **회원 엑셀 등록:** 회원 명단 → 엑셀로 가져오기 → `.xlsx` 또는 UTF-8 CSV 선택 → 시트·제목 행·등록 기수·MEMBERS/ALUMNI 확인 → 명단 미리보기 → 선택 인원 초안 등록. 이후 목록에서 선택하여 일괄 공개한다. AI는 열 연결을 추천하며 실제 이름·학과·학번은 원본 셀에서 읽는다. 원본 파일·회원 값은 AI에 보내지 않고, 허용된 헤더 종류와 값의 형식만 전달한다. 기수 열이 없는 혼합 명단은 기수별 파일로 먼저 나눈다. 학번은 입학연도 두 자리만 저장하며, 숨긴 행·수식·셀 색상·사진은 가져오지 않는다. 같은 기수의 같은 이름은 휴지통까지 중복 확인하며 덮어쓰지 않는다. 동명이인은 개별 확인한다. 미수료·탈퇴 비고는 기본 선택에서 제외하지만 최종 포함 여부는 담당자가 확인한다.
- **모집:** 안내 문구·기수·접수 일정·지원 링크를 저장한다. 한국 시간으로 입력하며 다음 사이트 배포에서 반영된다.
- **삭제:** 비공개는 원본을 유지한다. 휴지통은 공개를 중단하고 30일간 복원할 수 있다. 이후 관리자가 사이트를 사용할 때 시간당 한 번 소량씩 정리한다. 앱이 만든 Drive 파일은 휴지통으로 이동하고 연결된 DB 자료를 정리한다. 이전 Notion용 Drive 원본은 자동 삭제하지 않는다.

비공개 전환은 이미 다운로드한 파일이나 공개된 이미지 사본을 회수하지 않는다. 공개 사이트에는 개인정보나 비밀 자료를 올리지 않는다.

목록의 검색·학기·기수·페이지와 편집 중인 항목은 주소에 남습니다. 새로고침하거나 브라우저 뒤로가기를 사용해도 해당 위치를 다시 엽니다. PDF 교체에서 돌아가면 원래 리포트 편집 화면을 열며, 저장소 연결 화면을 거쳐도 최대 30분간 같은 탭의 교체 대상과 목록 조건을 기억합니다. 중복 PDF는 ‘기존 리포트 열기’로 연결된 글을 엽니다. 저장하지 않은 입력이 있으면 이동 전 확인하며, 첨부 업로드 중에는 저장·게시·다른 메뉴 이동을 잠시 제한합니다. 이미 게시한 동일 초안은 ‘게시됨’으로 표시되고, 입력을 바꾸면 ‘저장 전 변경’으로 바뀝니다. 변경한 내용은 초안 저장 후 다시 게시합니다.

## 인수인계와 복구

관리자 로그인은 같은 브라우저에서 인증 시점부터 24시간 유지된다. 사용하지 않아도 30분 만에 종료되지 않으며, 계속 사용해도 24시간을 넘겨 자동 연장되지는 않는다. 로그아웃은 즉시 세션을 해제하고, 패스키 삭제·복구 인수인계는 관련 기존 세션을 해제한다. 패스키 추가·삭제, 연결 키 교체 등 보안 설정의 별도 재인증은 유지한다. 적용 전에 발급된 세션은 기존 만료 시각까지 유효하며, 다음 로그인부터 새 정책이 적용된다.

다른 컴퓨터에서는 로그인 화면의 **휴대폰 QR로 로그인**을 사용한다. 휴대폰에 `admin.pnusmp.com` 패스키가 저장·동기화되어 있어야 하며, 두 기기를 가까이 두고 Bluetooth와 인터넷을 켠다. 브라우저가 표시하는 QR을 휴대폰 카메라로 스캔해 휴대폰에서 인증한다. 일부 환경에서는 먼저 ‘다른 기기 사용’ 또는 ‘iPhone·iPad·Android 기기’를 선택해야 한다. 휴대폰에 패스키가 없다면 기존 기기로 로그인한 후 **로그인·인수인계 → 패스키 추가**의 두 번째 인증 창에서 휴대폰을 선택해 등록한다. 공용 컴퓨터에서는 사용 후 로그아웃한다.

QR은 브라우저의 WebAuthn/FIDO 화면이며 웹사이트가 QR이나 로그인 토큰을 직접 생성·배포하지 않는다. QR 버튼은 `hints: ["hybrid"]`로 화면 선택만 안내하고 2분의 인증 대기 시간을 제공한다. 서버의 5분 일회용 challenge, 등록 키·origin·RP ID·사용자 확인 검증 및 24시간 세션 정책은 동일하다. 새 서비스·저장소·폴링은 추가하지 않는다. [Google 공식 안내](https://developers.google.com/identity/passkeys/use-cases), [Chrome hints 안내](https://developer.chrome.com/blog/passkeys-updates-chrome-129).

패스키와 보관한 복구 코드로 새 담당자에게 인수인계한다. 복구 코드를 저장소·채팅에 올리지 않는다. Drive 연결은 학회 계정을 유지하고, 연결 상태에서 인증 만료/저장 한도를 확인한다.

D1은 무료 플랜에서 최근 7일 Time Travel 복구를 제공한다. 큰 변경 전에는 두 DB를 별도로 SQL 내보내기하여 비공개 장소에 보관한다. 내보내기에는 인증 관련 자료가 포함되므로 공개 저장소·Actions artifact에 업로드하지 않는다. 이관 시점의 전체 SQL 및 콘텐츠 스냅샷은 담당자 로컬 비공개 폴더에 보관했다. 자동 외부 백업을 추가로 설정한 것은 아니다.

긴급 롤백은 운영 담당자가 게시 작업을 중지하고, 보관한 공개 데이터 스냅샷과 이전 코드로 복원한 뒤 관리 원본 설정을 되돌린다. 관리자에서 새로 만든 자료를 먼저 별도 보존해야 한다. 오래된 Notion과 새 관리자 데이터를 동시에 자동 동기화하지 않는다. 상세 실행 기록·복원 명령은 비공개 인수인계 자료를 사용한다.

## 코드 경계와 운영 상한

- `admin-lab/`: 관리자 UI. 기존 패스키·세션·CSRF 보호를 사용한다.
- `cms/`: 작성/승인, 순서, 게시 준비, 보관 정리. 작성 DB와 공개 읽기 모델을 분리한다.
- `admin-cloud/`: 인증, PDF 저장, 앱이 만든 Drive 파일 접근. 인증 DB는 공개 CMS DB와 분리한다.
- `free/`: 기존 공개 화면과 가벼운 읽기 API. 방문자 요청에서 Notion이나 AI를 호출하지 않는다.
- GitHub Actions: 승인한 새 PDF만 변환하고 파일 검증·정적 배포 후 공개한다. 방문자가 많아도 PDF를 다시 생성하지 않는다.

안전 상한은 CMS 2,500건, 본문 256 KB·400블록, 본문/승인/최근 이력 합계 64 MiB, 사진·공지 첨부 원시 용량 합계 100 MiB이다. 새 PDF 준비는 하루 최대 10건·한 작업 최대 2건이다. PDF 원본 정적 보관 2 GiB, 읽기 묶음 4 GiB, 정적 파일 총 18,000개에서 배포를 멈춘다. 초과 시 기존 사이트를 보존하고 유료 전환하지 않는다. 업로드·Drive·AI 자체의 기존 제한도 별도로 유지한다.

이 상한은 Cloudflare·Google·GitHub의 서비스 한도를 없애지 않는다. 무료 서비스 장애·계정 할당량·큰 PDF 전송·인증 만료는 여전히 운영자가 확인해야 한다.

엑셀은 파일 2 MiB·시트 20개·행 1,000개·열 40개, 일괄 등록은 한 번에 100명으로 제한한다. 압축 해제 크기를 제한하고 외부 XML 참조·매크로 실행·수식 계산·하이퍼링크 요청을 하지 않는다. AI 열 연결은 기존 PDF 입력 보완과 합산해 하루 10회이며 같은 형식의 결과를 7일간 재사용한다. 실패 시 자동 재호출하지 않고 직접 열 연결을 제공한다. 저장은 한 SQL 문장으로 처리하므로 오류가 나면 해당 묶음 전체가 취소되며, 재전송으로 중복 명단을 만들지 않는다.
# 기수별 회원 관리

회원 명단을 열면 기수별로 구분·전체 인원·공개·초안 현황을 표시합니다. 기수 이름 또는 ‘명단 관리’를 눌러 해당 기수의 회원 수정, 엑셀 가져오기, 일괄 공개·비공개·휴지통 처리를 합니다. ‘기수 추가’에서 번호를 입력하면 빈 명단을 열며, 첫 회원을 등록한 뒤 기수 목록에 남습니다. 별도의 기수 DB를 복제하지 않고 회원 자료를 집계하므로 기존 회원 주소·공개 상태는 유지됩니다.

사이트 현황은 실시간 화면이 아닙니다. 다운로드·PDF 이벤트는 보통 3초 후 서버로 전송하고, 대시보드 집계본은 최소 1시간 간격으로 기존 15분 주기의 게시 작업에서 갱신합니다. GitHub 예약 실행 및 Cloudflare 통계 처리 지연이 더해질 수 있습니다. 관리자 화면은 진입 또는 상단 새로고침 시 저장된 집계본을 읽습니다.
