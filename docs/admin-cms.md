# 관리자 CMS 운영

2026-10-27부터 콘텐츠 관리의 기준은 별도 관리자 화면이다. Notion 원본은 이관 기록과 복구 자료로 보존하며, 이후 Notion 변경은 공개 사이트에 반영하지 않는다. 기존 글 주소와 사이트 디자인은 유지한다.

## 담당자 사용법

- **리포트:** PDF 등록 → 자동 추출된 기업명·종목코드·제목 확인 → 입력 승인 → 게시 목록에 추가 → 게시. 새 PDF의 표지와 전체 페이지 준비가 끝나야 공개된다. 작업은 보통 15분 이내 시작하지만 파일 크기·대기열·플랫폼 상태에 따라 더 걸릴 수 있다. 실패 상태에서 게시를 재시도할 수 있으며 기존 공개본은 유지된다.
- **수정·교체:** 제목 등의 수정은 초안 저장 후 게시한다. PDF 교체도 기존 글에서 시작해 같은 주소를 유지한다. 입력 후보는 반드시 원문과 대조한다.
- **순서:** 리포트와 공지 목록의 손잡이를 파란 삽입선에 놓는다. 위·아래 버튼도 지원한다. 공개된 글의 순서는 바로 반영된다. 검색·학기 필터로 대상을 찾을 수 있다.
- **공지:** 새 공지사항 → 제목·게시일·본문 편집 → 미리보기 → 초안 저장 → 게시. 사진, 제목, 목록, 강조, 인용, 표, 첨부를 지원한다. 사진은 브라우저에서 크기를 줄이며 PDF·ZIP 첨부는 개당 1.4 MB 이하이다. 원본 Notion 서식 중 지원하지 않는 새 블록을 자동 변환하는 기능은 없다.
- **회원:** 기수·구분·이름·학과·학번 표시·직책·사진을 수정하고 게시한다. 같은 기수에서는 회장, 부회장, 기장, 가나다순이다.
- **모집:** 안내 문구·기수·접수 일정·지원 링크를 저장한다. 한국 시간으로 입력하며 다음 사이트 배포에서 반영된다.
- **삭제:** 비공개는 원본을 유지한다. 휴지통은 공개를 중단하고 30일간 복원할 수 있다. 이후 관리자가 사이트를 사용할 때 시간당 한 번 소량씩 정리한다. 앱이 만든 Drive 파일은 휴지통으로 이동하고 연결된 DB 자료를 정리한다. 이전 Notion용 Drive 원본은 자동 삭제하지 않는다.

비공개 전환은 이미 다운로드한 파일이나 공개된 이미지 사본을 회수하지 않는다. 공개 사이트에는 개인정보나 비밀 자료를 올리지 않는다.

## 인수인계와 복구

패스키와 보관한 복구 코드로 새 담당자에게 인수인계한다. 복구 코드를 저장소·채팅에 올리지 않는다. Drive 연결은 학회 계정을 유지하고, 연결 상태에서 인증 만료/저장 한도를 확인한다.

D1은 무료 플랜에서 최근 7일 Time Travel 복구를 제공한다. 큰 변경 전에는 두 DB를 별도로 SQL 내보내기하여 비공개 장소에 보관한다. 내보내기에는 인증 관련 자료가 포함되므로 공개 저장소·Actions artifact에 업로드하지 않는다. 이관 시점의 전체 SQL 및 콘텐츠 스냅샷은 담당자 로컬 비공개 폴더에 보관했다. 자동 외부 백업을 추가로 설정한 것은 아니다.

긴급 롤백은 운영 담당자가 게시 작업을 중지하고, 보관한 공개 데이터 스냅샷과 이전 코드로 복원한 뒤 관리 원본 설정을 되돌린다. 관리자에서 새로 만든 자료를 먼저 별도 보존해야 한다. 오래된 Notion과 새 관리자 데이터를 동시에 자동 동기화하지 않는다. 상세 실행 기록·복원 명령은 비공개 인수인계 자료를 사용한다.

## 코드 경계와 운영 상한

- `admin-lab/`: 관리자 UI. 기존 패스키·세션·CSRF 보호를 사용한다.
- `cms/`: 작성/승인, 순서, 게시 준비, 보관 정리. 작성 DB와 공개 읽기 모델을 분리한다.
- `admin-cloud/`: 인증, PDF 저장, 앱이 만든 Drive 파일 접근. 인증 DB는 공개 CMS DB와 분리한다.
- `free/`: 기존 공개 화면과 가벼운 읽기 API. 방문자 요청에서 Notion이나 AI를 호출하지 않는다.
- GitHub Actions: 승인한 새 PDF만 변환하고 파일 검증·정적 배포 후 공개한다. 방문자가 많아도 PDF를 다시 생성하지 않는다.

안전 상한은 CMS 2,500건, 본문 256 KB·400블록, 본문/승인/최근 이력 합계 64 MiB, 사진·공지 첨부 원시 용량 합계 100 MiB이다. 새 PDF 준비는 하루 최대 10건·한 작업 최대 2건이다. PDF 원본 정적 보관 2 GiB, 읽기 묶음 4 GiB, 정적 파일 총 18,000개에서 배포를 멈춘다. 초과 시 기존 사이트를 보존하고 유료 전환하지 않는다. 업로드·Drive·AI 자체의 기존 제한도 별도로 유지한다.

이 상한은 Cloudflare·Google·GitHub의 서비스 한도를 없애지 않는다. 무료 서비스 장애·계정 할당량·큰 PDF 전송·인증 만료는 여전히 운영자가 확인해야 한다.
