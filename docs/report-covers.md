# 리포트 표지 준비와 복구

현재는 GitHub Actions가 원본 PDF 첫 페이지를 렌더링하고, 목록용 720px WebP와 상세용 최대 2048px WebP를 준비합니다. 이미지는 Cloudflare 정적 파일로 배포하며 메타데이터는 D1에 저장합니다. Vercel Blob 설정이나 방문자 요청 중 PDF 변환은 사용하지 않습니다.

## 평상시

Drive에 PDF를 올리고 Notion 리포트에 파일 링크·공개·게시일을 설정합니다. 서명된 변경 알림/보조 동기화 → 게시 대기열 → GitHub 게시 작업 → 이미지 배포 → 최신 공개 여부 확인 순서로 진행합니다. 처음 게시할 때 준비 시간이 필요하며 정확한 완료 시간은 보장하지 않습니다. [실행 상태와 수동 복구](operations.md)를 참고하세요.

제목·본문 변경이나 공개 해제 후 재공개 때도 같은 PDF이면 기존 표지를 재사용합니다. 게시 작업은 PDF 바이트의 SHA-256을 비교하므로 원본 다운로드는 발생할 수 있지만 내용이 같으면 이미지 렌더링·새 정적 배포를 생략합니다. 공개 해제는 보관된 표지 기록을 유지하고, 실제 Notion 항목 삭제·CMS 이탈은 기록을 제거합니다.

동일 Drive 파일 ID에 PDF 버전만 바꾼 경우 Notion 변경 알림은 발생하지 않습니다. GitHub 게시 워크플로의 `refresh-report`와 해당 Notion 페이지 ID를 사용하세요. 글 삭제/재생성이나 제목의 임의 변경은 필요하지 않습니다. 원문이 바뀌면 새 표지, 같으면 기존 표지가 유지됩니다.

## 저장과 안전장치

- `/report-covers/<페이지 ID>/<SHA-256>.webp`는 내용별 정적 이미지입니다. 다음 배포 전 현재 사용하는 모든 이미지를 확보하고 해시를 검사합니다. 캐시가 사라졌다는 이유로 기존 표지를 누락한 채 배포하지 않습니다.
- `free_report_covers`는 재공개 때 사용할 검증된 PDF 해시/표지 주소를 보관하고 `free_content`는 현재 공개 자료를 나타냅니다. 둘은 의도적으로 분리돼 있습니다.
- 새 표지는 게시 완료 시점의 최신 소속·공개·수정 버전이 맞을 때만 연결합니다. 한 글 실패로 원본 PDF나 다른 글을 삭제하지 않습니다.
- 실패는 최대 5회 자동 시도 후 대기합니다. 원인을 고친 뒤 관리 워크플로 `retry-failed`로 해당 글만 재시도합니다.
- 공개 이미지 주소나 이미 내려받은 파일은 Notion 공개 해제만으로 회수되지 않습니다. 민감한 내용을 표지·공지 이미지에 올리지 않습니다.

## 코드

`free/jobs/prepare.ts`: PDF 해시·WebP 준비. `free/jobs/publish.ts`: 대기열·이미지 보전·배포. `free/server/jobs.ts`: 작업 임대와 최종 공개 검증. `free/server/publisher.ts`: 제한된 자동 실행 요청. `free/jobs/maintenance.ts`: 상태/재시도/수정 PDF 확인. 초기 웹훅 연결은 [Cloudflare 연결 안내](free-webhook.md)를 사용합니다.

## 읽기 시작 속도

게시할 때 앞 3페이지를 최대 2048px WebP로 함께 만듭니다. 방문자는 목록 표지를 즉시 재사용하고, 상세 공개 상태를 확인한 뒤 준비된 1~3페이지를 넘겨볼 수 있습니다. PDF가 준비되면 선택한 페이지에서 이어집니다. 새로 연 페이지와 캐시에 없는 이미지는 네트워크 속도의 영향을 받습니다.

게시 작업은 pikepdf/qpdf로 화질을 낮추지 않는 선형화 PDF도 준비합니다. 원본 다운로드는 Drive 원본을 유지합니다. 열람용 사본은 개별 24 MiB 이하, 최신 자료 최대 32개·합계 512 MiB까지만 배포하고, 없는 사본·상한 초과·원본 변경 시 기존 Drive 경로로 전환합니다. 직접 정적 주소로 PDF에 접근할 수 없으며 기존 공개 검증 API를 거칩니다. 같은 Drive ID의 파일 교체를 감지하기 위해 원본 크기·수정 시각을 최대 5분마다 확인합니다.

기존 자료는 게시 작업이 없을 때 하루 최대 20건씩 준비합니다. 기존 하루 50건 준비 한도 안에서 처리하므로 평소 게시를 위한 여유를 남깁니다. 서명·암호화 PDF는 최적화하지 않으며, 새 준비가 실패하면 기존 자료를 유지합니다. Python 변환 도구는 방문자 서버가 아닌 GitHub 게시 작업에서만 실행됩니다.
