# 관리자 Drive 저장 연결 시험

운영 pnusmp.com 및 Notion과 분리된 관리자 시험 기능이다. 기존 Notion·Drive 파일을 옮기거나 지우지 않는다. 관리자에서 승인해도 운영 사이트에 게시되지는 않는다.

## 사용 순서

1. 관리자에 기존 패스키로 로그인하고 **파일 저장소**를 연다.
2. 아래 최초 연결을 완료한다. 연결 전 기존 파일과 새 업로드는 종전 시험 D1에 저장된다.
3. 연결 후 새 PDF를 등록하면 학회 Drive의 **SMP 관리자 시험 · PDF 원본** 비공개 폴더에 저장한다. 글 정보·표지·검증 값은 D1에 둔다. 기존 D1 PDF는 자동 이동하지 않는다.
4. 기업명·종목코드 등 입력 후보를 검토하고 시험 승인한다.
5. 수정하거나 PDF를 교체해도 이전 승인본은 따로 보관한다. 편집 화면의 **승인본 PDF 확인**에서 이전 원문을 받을 수 있다. 새 승인 후에만 승인본 연결이 바뀐다.
6. 휴지통에서는 글과 파일을 복원할 수 있다. 영구 삭제 시 글은 목록에서 제거되지만 파일은 30일간 격리한다. 이후 관리자 접속 시 정리하며 Drive 파일은 휴지통으로만 이동한다. 영구 삭제한 글을 관리자 화면에서 복원하는 기능은 없다.

## Google 최초 연결

학회 소유 Google Cloud 프로젝트를 사용한다. 결제 계정을 연결하거나 유료 플랜·추가 할당량을 신청하지 않는다. API 인증 앱은 저장소 연결을 위한 것으로, 관리자 로그인은 기존 패스키를 유지한다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 학회 프로젝트를 선택하거나 만든다. 최초 약관·본인 인증은 계정 소유자가 직접 확인한다.
2. **APIs & Services → Library → Google Drive API → Enable**.
3. **Google Auth Platform → Branding / Audience / Data Access**에서 학회 관리용 앱을 준비한다. Gmail 개인 계정은 External을 사용한다. 요청 범위는 `https://www.googleapis.com/auth/drive.file` 하나이다. 전체 Drive 접근 범위는 추가하지 않는다.
4. **Clients → Create client → Web application**. Authorized redirect URI는 정확히 `https://admin.pnusmp.com/api/storage/drive/callback`.
5. 내려받은 클라이언트 JSON을 관리자 **파일 저장소 → 연결 앱 JSON 불러오기**에서 입력한다. 채팅·GitHub·공개 Drive에 올리지 않는다.
6. **학회 Google 계정 연결**을 누르고 서버에 허용된 학회 계정으로 Google 동의를 완료한다.
7. 관리자에 돌아와 **Drive 연결 완료**를 누른다. 관리자 세션이 만료됐다면 패스키로 다시 로그인한다. 이 확인 전에는 Drive에 파일이나 폴더를 쓰지 않는다.
8. 실제 PDF 한 개 등록 → 내려받은 원본 확인 → 수정 → 승인 → PDF 교체 → 이전 승인본 확인 → 휴지통·복원을 검증한다.

Google 앱이 External / Testing이면 Drive 갱신 토큰이 7일 뒤 만료된다. 테스트 사용자에 학회 계정을 추가하고 단기 검증할 수 있으나, 운영 전 앱의 게시 상태와 Google 요구사항을 확인해야 한다. Production으로 설정해도 권한 철회 등으로 연결은 만료될 수 있다. `drive.file`은 비민감 범위이며 앱이 만든 파일/명시적으로 허용된 파일에만 접근한다. 이 구현에는 기존 파일을 선택하는 Picker 기능이 없으므로 기존 Notion 원본에 접근 권한을 넓히지 않는다.

### 장기 연결과 인수인계

2026-10-27 학회 앱의 Audience를 **In production**으로 전환했다. 이 설정은 관리자 자료를 공식 홈페이지에 게시하거나 Drive 파일을 공개하는 설정이 아니다. 앱의 홈페이지와 개인정보 안내는 `https://admin.pnusmp.com/`, `https://admin.pnusmp.com/privacy`이다. 서버의 학회 계정 허용 목록과 `drive.file` 범위는 유지한다. 결제 계정을 연결하거나 유료 API 할당량을 신청하지 않는다.

전환 후에는 관리자 **파일 저장소 → Google 연결 갱신 → 같은 학회 계정으로 승인 → Drive 연결 완료**를 수행해 새 연결을 저장한다. Google 설정만 바꾸었다고 기존 테스트 토큰이 영구 토큰으로 바뀌었다고 가정하지 않는다. 완료 후 **남은 용량 확인**과 기존 시험 PDF 열기를 확인한다. Google에 원래 폴더를 다시 연결하므로 새 앱이나 새 저장 폴더를 만들 필요가 없다.

갱신은 저장·조회에 필요할 때 수행한다. 토큰 유지를 위한 상시 타이머·주기적인 API 호출은 추가하지 않는다. 권한 철회, 6개월 미사용, Google 정책 변경 등으로 재승인이 필요할 수 있으므로 연결 오류 시 동일한 메뉴에서 복구한다. 기존 연결이 실패해도 자료를 삭제하지 않으며, 새 연결의 계정·폴더 확인에 실패하면 기존 연결을 보존한다.

인수인계 시 패스키 등록/회수 절차와 별도로 학회 Google 계정의 복구 수단을 점검하고, 현재 프로젝트·OAuth 클라이언트·Drive 폴더를 유지한다. OAuth 앱을 삭제하거나 새 앱으로 교체하면 기존 파일 접근이 끊길 수 있다. 비밀 키는 필요할 때만 **연결 키 교체** 절차로 갱신한다. 접근 철회와 자료 삭제 문의 방법은 공개 개인정보 안내에 명시한다.

연결 오류에 `Google 인증 교환` 또는 `Google 계정 확인`이 나오면 해당 단계와 HTTP 상태를 먼저 확인한다. 원문 오류 응답이나 OAuth 코드·토큰을 로그에 남기지 않는다. Cloudflare의 네이티브 `fetch`는 클래스 메서드처럼 바인딩해 호출하면 안 되며 `redirect: "error"`도 지원하지 않는다. 전역 함수로 호출하고 `manual`로 받은 리디렉션을 거부한다. 단, Drive의 위치 헤더 없는 HTTP 308 응답은 분할 업로드 수신 확인이므로 유지한다.

서버의 허용 계정은 Git에 들어가지 않는 `.smp-tools/admin-cloud-target.json`의 `driveAccountEmail`에서 배포 변수로 전달된다. 연결 계정 이메일은 서버에서도 확인한다. OAuth 앱 자체의 교체는 차단한다. 같은 클라이언트 ID의 비밀 키는 **파일 저장소 → 연결 키 교체**에서 기존 패스키로 재인증한 뒤 교체할 수 있다. 새 키로 학회 계정과 기존 비공개 폴더를 확인한 뒤 설정을 원자적으로 저장하며, 실패하면 이전 설정을 유지한다. 성공 확인 전에 Google의 이전 키를 폐기하지 않는다.

## 보관·삭제 원칙

- PDF는 파일 버전별로 불변 보관한다. 글 수정과 승인본은 별도이며, 승인 포인터가 이전 파일을 가리키는 동안 원본을 지우지 않는다.
- 현재 파일·이전 버전·다른 글 중 하나라도 참조하면 자동 정리 대상에서 제외한다.
- 파일 소유자·전용 폴더·앱 표시·원문 SHA-256·공개 범위를 확인한 후에만 Drive 휴지통으로 이동한다. 공유되거나 직접 수정된 파일은 자동 정리를 멈춘다.
- 전송 중단 파일도 서버 파일 번호를 남기고 30일 보류한다. 전송 응답만 유실된 경우 같은 파일을 다시 선택해 재개한다. 전송 대기는 30분 뒤 정리 대상이 된다.
- Drive 정리는 관리자 접속 시 최대 시간당 1회·2개. 실패 시 연결 정보를 보존하고 다음 날 재시도하며, 3회 실패 후 자동 재시도를 멈춘다. 관리자 접속이 없으면 정리도 진행되지 않는다.
- 영구 삭제된 글의 원본이 Drive 휴지통으로 이동한 뒤에는 Google의 휴지통 보관 정책이 적용된다. 별도 백업을 대체하지 않는다.
- 공지사항 CRUD·사진 저장은 기존 시험 D1 방식이다. 공지의 불변 승인본/Drive 사진 이관은 이 단계의 범위에 포함되지 않는다.

## 무료 운영 제한과 남은 검증

- Drive 연결 전 리포트 50개, 연결 후 500개. 휴지통 포함, 공지 100개.
- PDF당 32MiB·120쪽, 새 Drive 파일 하루 10개. 파일 교체도 새 파일로 계산한다.
- D1 원시 파일 보관 예산 200MiB: D1 PDF·표지·공지 사진·격리된 이전 파일을 합산한다. Drive PDF는 원본 대신 조각별 해시와 마지막 두 조각의 끝부분만 보관한다.
- 수정 이력은 별도 32MiB 또는 10,000개 중 먼저 도달하는 한도에서 새 이력 쓰기를 원자적으로 중단한다. 이력을 임의 삭제하지 않는다. 기존 승인본과 조회는 유지되며, 이력 백업·정리 절차가 이후 필요하다.
- 관리자 콘텐츠 요청 하루 5,000회·분당 600회, 일괄 수정/삭제 5개. 새 호출 경로는 Free D1 요청당 50-query 한도 검사를 통과해야 한다. 조회만으로 Google API를 계속 호출하거나 상시 동기화하지 않는다.
- Drive 계정의 실제 잔여 용량을 조회하고 원본 크기 외 64MiB 여유가 없거나 용량 확인에 실패하면 새 파일 생성을 중단한다. Gmail 등과 계정 용량을 공유한다.
- Cloudflare 무료 일일 한도는 같은 계정의 운영 사이트와 공유한다. 자체 제한은 사용량 억제 장치이며 무제한 보장이나 서비스 정책 고정을 뜻하지 않는다.
- Google Drive API 표준 사용은 현재 추가 비용이 없지만, 공식 문서에 2026년 중 할당량 초과 과금 계획이 안내되어 있다. 결제 연결·할당량 자동 증액 없이 시험하고 운영 전 해당 프로젝트의 실제 할당량을 재확인한다.
- 실제 Google 연결·업로드·갱신은 OAuth 앱이 준비된 뒤 검증한다. 모의 API 테스트만으로 외부 계정 연결 성공을 주장하지 않는다.

## 운영 전환에 남은 단계

1. 실제 학회 Drive 연결과 PDF 저장·다운로드·재로그인 검증.
2. 보관 중인 Notion 데이터의 읽기 전용 참조를 연결하고 기존 글 ID·URL·표지·전체 페이지 미리보기를 대조. 현재 파일 제한을 초과하는 기존 PDF도 별도 처리 설계가 필요하다.
3. 공지 본문·사진 및 회원 명단의 관리자 편집/승인/이관 범위를 확정.
4. `report_jobs`는 시험 승인 이력을 보관할 뿐이다. 정적 페이지 생성·표지/전체 PDF 미리보기·검색/사이트맵 갱신을 실행하는 공개 게시 소비자는 아직 연결하지 않았다.
5. 공개 전환 전 shadow 게시·내용 비교·삭제 중복 방지·운영 소유권 전환·롤백을 리허설한다. 그때까지 Notion 웹훅·Apps Script 삭제 연동은 유지한다.

## 복구와 유지보수

`schema.sql` 및 `history-budget.sql`은 시험 D1에만 추가 적용한다. 배포 스크립트는 Worker·DB·도메인·바인딩을 검사해 운영 대상으로의 배포를 거부한다.

Google 비밀값은 기존 세션 서명 키에서 HKDF로 파생한 키로 AES-GCM 암호화한다. DB와 `SESSION_SIGNING_KEY`, OAuth 앱을 함께 보존해야 복구할 수 있다. 서명 키나 도메인을 바꾸기 전 재암호화 이관이 필요하다. 키를 무작정 바꾸거나 OAuth 앱을 삭제하지 않는다. 토큰·PDF 본문은 로그에 출력하지 않는다.

Drive 파일 등록 전에는 종전 Worker로 되돌려 D1 파일을 읽을 수 있다. **Drive 등록 이후 종전 Worker로 단순 롤백하면 Drive 원본을 읽지 못한다.** 장애 시 새 쓰기를 중단하고 Drive 호환 버전으로 복구한다. 배포 전 DB 백업을 복원할 때는 이후 생성된 파일·수정사항과 참조 관계를 먼저 대조한다. 운영 사이트 전환은 별도 승인 전까지 하지 않는다.

검증 명령: `pnpm typecheck`, `pnpm test`, `node tests/admin-cms-render.mjs`, `pnpm test:admin:cloud`, `pnpm build:admin:cloud`. Drive API는 모의 제공자를 주입해 인증 실패·중단 후 재개·잘못된 체크섬·삭제 실패를 재현한다. workerd 테스트는 로컬 D1에서 32MiB 전체 전송·응답 유실·원본 일치·승인본·CRUD를 검증한다.

`pnpm test:admin:drive`는 실제 workerd 네이티브 통신을 사용해 인증 교환·계정 확인·폴더 생성·용량 조회를 검증한다. 외부 요청은 로컬 모의 Google 서비스로만 전달하며, 실제 Google/Cloudflare 계정 데이터는 사용하지 않는다. Node 모의 테스트만으로 발견되지 않는 Workers 통신 호환성을 확인하기 위해 연결 코드 변경 시 함께 실행한다.

공식 근거: [Drive 업로드](https://developers.google.com/workspace/drive/api/guides/manage-uploads), [Drive 권한](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [OAuth 만료](https://developers.google.com/identity/protocols/oauth2), [Drive 한도·요금](https://developers.google.com/workspace/drive/api/guides/limits), [D1 한도](https://developers.cloudflare.com/d1/platform/limits/), [D1 요금](https://developers.cloudflare.com/d1/platform/pricing/).
