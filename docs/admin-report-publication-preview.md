# 관리자 승인 리포트 → 공개 사이트 연결 시험

> 2026-10-27 관리자 CMS 전환 이후 현재 사용법과 운영 기준은 [관리자 CMS 운영](admin-cms.md)을 따릅니다. 이 문서의 Notion 동기화·시험 운영 설명은 이전 구조의 기록입니다.

이 문서는 **별도 브랜치의 로컬 통합 시험**을 설명한다. 후속으로 2026-10-27 실제 관리자 승인본 한 건을 별도 온라인 시험 Worker에 게시했다. 온라인 범위·제한·검증 결과는 [실자료 온라인 게시 시험](./admin-report-online-trial.md)을 따른다. 기존 Notion 동기화와 운영 사이트는 전환하지 않았다.

## 구현한 경로

```text
관리자 업로드 → 수정본 저장 → 원문 확인 후 승인
                                  ↓
                         승인본 전용 읽기 API
                                  ↓
                  PDF 검증 → 표지·첫 3쪽·전체 페이지 준비
                                  ↓
                  별도 게시 DB에 목록·상세·검색 동시 반영
                                  ↓
                 기존 공개 사이트 UI에서 열람·원문 다운로드
```

- `admin-cloud/publication-source.ts`: 불변 승인본과 승인 당시 PDF를 읽는다. 초안, 추출 근거, Drive ID, OAuth 토큰은 내보내지 않는다. 휴지통 문서와 미래 발표일은 제외한다. 휴지통 복원 후에는 다시 승인해야 한다.
- `admin-cloud/publication-export.ts`: 전용 `REPORT_EXPORT_KEY` 또는 유효한 `REPORT_EXPORT_SCOPE`가 없으면 404다. 최대 두 개의 지정 문서와 24시간 이내 만료로 제한하며 승인 목록·해당 승인본 PDF 청크만 읽을 수 있다. 임의 Drive 파일, 수정 API, 브라우저 세션 권한을 제공하지 않는다. 온라인 시험에 사용한 임시 키는 준비 완료 후 폐기했다.
- `admin-publication/model.ts`: 승인 데이터와 공개 필드의 계약, 작업 한도다. 원본 PDF는 기존 청크 기반 식별값으로 확인하며, 이미지/페이지 묶음은 별도 SHA-256으로 확인한다.
- `admin-publisher/`: 다운로드·변환·무결성 확인·게시 트랜잭션·실패 재시도를 담당한다. 방문자 Worker에서 PDF 변환을 실행하지 않는다.
- `admin-publisher/preview.ts`: 시험 DB의 승인본을 공개 사이트 읽기 경로에 주입한다. 운영 환경변수나 HTTP 매개변수로 켤 수 없다. 관리자 소유가 아닌 글은 기존 Notion 공개 확인 경로를 유지한다.

## 게시 동작

| 작업 | 시험 사이트 결과 |
| --- | --- |
| 새 PDF 저장, 승인 전 편집 | 공개 목록에 나오지 않음 |
| 승인 | 파일 준비 완료 후 목록·상세·검색에 함께 반영 |
| 공개본의 초안 수정 | 이전 승인본 유지 |
| 동일 PDF의 제목 등 수정 후 재승인 | 검증된 표지·전체 페이지 재사용, PDF 재다운로드/재변환 없음 |
| PDF 교체 | 새 승인본 준비에 성공할 때까지 이전 게시본 유지 |
| 드래그 순서 변경 | 기존 학기 우선 정렬 안에서 순서 반영, PDF 재변환 없음 |
| 휴지통 이동 | 다음 게시 실행에서 목록·상세·다운로드 제거 |
| 휴지통 복원 | 자동 재공개하지 않음; 새 승인 필요 |
| 원본 손상·변환 실패·용량 상한 | 실패 기록 후 제한된 재시도; 기존 게시본 유지 |
| 승인 내용이나 순서가 준비 중 바뀜 | 준비 결과의 게시를 거부하고 다음 실행에서 다시 확인 |

파일은 먼저 준비하고 마지막 DB 트랜잭션에서 게시한다. SQL 오류가 나면 목록·상세·검색의 변경을 함께 되돌린다. 불완전한 내보내기를 빈 목록으로 취급해 전체 삭제하지 않는다. Notion 소유 글과 ID가 충돌하면 덮어쓰지 않고 중단한다.

휴지통 반영은 게시 실행 시점 기준이다. 이 시험에 예약 작업/웹훅이 켜져 있는 것은 아니며, 두 DB 사이의 즉시 일관성까지 구현한 것은 아니다. 기존 준비 자산을 즉시 영구 삭제하지 않아 게시 실패/복구 때 사용할 수 있다. 장기 자산 정리는 별도 참조 확인과 보존 기간이 필요하다.

## 무료 사용량 보호

이 수치는 서비스 제공자의 무료 할당량이 아니라 **시험 코드 자체의 상한**이다. 실제 운영 허용량은 계정의 다른 작업과 합산해서 확인해야 한다.

- 새 PDF 준비: 실행당 최대 2개, UTC 날짜 기준 하루 최대 10회. 실패한 시도도 횟수에 포함한다.
- 같은 승인본 실패: 최소 15분 간격, 최대 3회. 같은 입력을 무한 반복하지 않는다.
- 승인 목록 최대 500건, PDF당 32 MiB·120쪽. 기존 관리자 업로더의 별도 시험 한도는 높이지 않는다.
- 준비 자산: 별도 로컬 폴더 256 MiB·2,000개 파일, 전체 페이지 묶음 최대 24 MiB. 상한에 닿으면 새 게시를 보류한다.
- 전용 읽기 API: 분당 300회·하루 1,600회. 게시 클라이언트도 실행당 300요청·요청당 20초로 제한한다. PDF는 256 KiB 청크로 확인한다.
- 중복 실행은 10분 임대로 막는다. 작업 완료 직전에도 임대 소유를 확인한다.
- 바뀌지 않은 승인본은 PDF 다운로드나 변환을 하지 않는다. 방문자 요청에서 AI를 호출하지 않는다.

시험 데이터는 로컬 SQLite와 로컬 파일에만 저장한다. 이번 검증으로 실제 Cloudflare/Drive 사용량, 신규 유료 서비스 또는 청구 설정이 추가되지 않는다. 전체 400여 건을 이 시험 상한에 한 번에 넣지 않는다.

## 재현

```sh
pnpm typecheck
pnpm test
pnpm build:admin:cloud
pnpm test:admin:drive
pnpm build:free:fixture
pnpm cms:preview-reports --out /absolute/private/new-publication-preview
```

Node 22.22 이상, 설치된 의존성을 사용한다. `--out`은 저장소 밖의 존재하지 않는 절대 경로여야 한다. http://127.0.0.1:3017/research 에서 확인한다. 다른 프로그램이 포트를 쓰고 있으면 먼저 확인한다. 이 화면은 Mac에서만 실행되는 검증용이며 온라인 관리자 서비스와 다르다.

두 개의 명시적인 합성 PDF를 실제 관리자 API에 업로드·승인하고, 공개 사이트와 같은 Worker/화면 코드를 사용한다. Google OAuth/Drive 응답 및 패스키 인증기는 테스트 대역이다. 실제 개인 PDF, 원격 계정 키, 원격 D1을 사용하지 않는다. `verification.json`, `preview.sqlite`, `assets/`가 출력된다. 브라우저 화면에는 합성 자료임을 `[게시 시험]` 제목으로 표시한다.

검증 범위:

- 전체 361개 자동 테스트: 기존 Notion 경로와 새 승인 게시 통합 테스트 6개 포함
- 별도 native workerd 검증: 패스키 세션, 모의 OAuth, 비공개 Drive 업로드, 승인 전 제외, 승인본 내보내기, PDF 바이트 일치
- 공개 UI: 목록, 상세, 첫 미리보기, 전체 3쪽 준비, 페이지 이동, 확대, 검색, 목록 복귀
- API: 원문 바이트 일치/Range 다운로드, 승인 없는 접근 거부, 원본 경로 직접 접근 거부
- 실패: 원본 손상, 새 PDF 준비 실패, 작업 한도, 동시 실행, 준비 중 승인 변경, SQL 트랜잭션 실패

이 결과는 실제 Google 계정의 연결 갱신이나 운영 배포 결과를 대신하지 않는다.

## 실제 전환 전에 남은 일

1. 별도 온라인 환경의 일회 게시 시험은 완료했다. 지정 문서·만료·전용 DB 표식을 확인하는 경로만 허용하며, 이 결과를 지속적인 운영 게시로 간주하지 않는다.
2. 운영 게시기는 이 로컬 클래스의 원격 DB 주소만 바꿔 사용하지 않는다. 원격 D1의 요청/바인딩/쿼리 한도에 맞춰 묶음 저장을 만들고, 정적 자산 업로드 완료와 DB 교체의 실패 복구를 검증한다.
3. 승인 revision과 실제 게시 revision, 보류·실패·재시도 상태를 관리자 화면에 표시한다. 현재 기존 ‘시험 승인’을 ‘운영 게시 완료’로 바꾸지 않는다.
4. Notion/관리자 문서별 관리 주체를 운영 게시·비공개·삭제 처리 전체에서 적용한다. Notion 작업이 관리자 문서를 덮어쓰거나 Drive 파일을 삭제하지 못하게 한다.
5. 기존 글 ID/주소·순서·공개 여부를 보존하는 실제 가져오기를 검증한다. `drive.file`은 기존 Notion 파일 전체의 읽기 권한이 아니므로 기존 파일 이관 방식과 소유권도 확인한다.
6. 스케줄/웹훅, 무료 사용량 합산, 비공개 처리 반영 지연, 백업 복원, 자산 정리, 이전 후 롤백을 소량 실자료로 시험한다.
7. 결과 확인 후에만 리포트 종류의 관리 주체를 전환한다. 공지·회원의 Notion 운영은 별개로 유지한다.

기존 전체 이전 점검표는 [notion-admin-migration.md](./notion-admin-migration.md)를 따른다.
