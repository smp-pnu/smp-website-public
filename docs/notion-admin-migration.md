# Notion → 관리자 CMS 이전 준비

현재 상태는 **오프라인 점검·시험 이관 단계**다. `admin-migration/`은 관리자 Worker와 공개 사이트에서 사용하지 않는다. 이 도구를 실행하거나 브랜치에 커밋해도 게시 원본, Notion, Drive, 운영 DB가 전환되지 않는다. 운영 전환 전 아래 조건을 별도로 구현·검증한다.

2026-10-27: 리포트 승인본을 기존 공개 사이트 화면에 연결하는 **별도 로컬 게시 시험**을 추가했다. 승인본 읽기, 표지·전체 페이지 준비, 목록/상세/검색/다운로드, 실패 시 기존 게시본 유지까지 검증한다. 실제 운영 전환·원격 키·자동 게시 작업은 활성화하지 않았다. 범위와 남은 전환 조건은 [관리자 리포트 게시 시험](./admin-report-publication-preview.md)에 정리했다.

같은 날 실제 인바디 승인본 한 건을 전용 DB·Worker의 [온라인 시험](./admin-report-online-trial.md)에 게시했다. 지정 문서의 임시 내보내기 키는 사용 후 폐기했으며, 자동 동기화·운영 전환은 계속 비활성 상태다.

## 준비 도구

```sh
pnpm cms:prepare-migration --snapshot /absolute/private/snapshot --out /absolute/private/new-rehearsal
```

Node 22.22 이상과 설치된 프로젝트 의존성을 사용한다. 출력 디렉터리의 부모는 미리 존재해야 한다. 스냅샷과 Git 저장소 밖의 **새 디렉터리**만 허용한다. API 키·네트워크·원격 DB는 사용하지 않는다.

입력은 Notion 데이터 소스 스키마/행, 공지 원문 블록, 운영 게시 스냅샷의 읽기 전용 내보내기다. `notion-snapshot-manifest.json`, `cloud-snapshot-manifest.json`의 `files`는 `{file,bytes,sha256}` 목록이다. 기본 필수 파일은 다음과 같다.

- `notion-summary.json`: `finishedAt`, `sources.{research,notice,members}.count`, `bodyErrors`
- `research-pages.json`, `notice-pages.json`, `members-pages.json`: 삭제되지 않은 원본 Notion 행 배열
- `notice-body-{compact-page-id}.json`: 각 공지의 중첩 원문 블록 배열
- `production-free_content.json`: 현재 운영 게시 메타데이터·준비된 본문·표지 정보

소스 요약과 행 수, 매니페스트에 기록된 모든 파일의 크기·SHA-256을 대조한다. 체크섬은 손상 탐지용이지 출처 인증 서명은 아니다. 내보내기를 신뢰할 수 있는 학회 계정에서 받아야 한다.

출력은 다음과 같다. 개인정보, 비공개 글, 서명된 첨부 주소가 들어 있으므로 공개 저장소·채팅·공개 Drive 폴더에 올리지 않는다.

| 출력 | 용도 |
| --- | --- |
| `migration-plan.json` | 원문, 기존 주소 ID, 공개 여부, 필드 대응, 파일 참조, 전환 차단 사유 |
| `rehearsal.sqlite` | 운영과 분리된 로컬 시험 DB. 모든 행이 `review-only` 상태 |
| `rehearsal-results.json` | 첫 삽입·두 번째 동일 입력의 중복 방지 결과 |
| `preserved-urls.json` | 이전 후 유지할 글 주소. 비공개 글도 포함하므로 비공개 보관 |

디렉터리 권한은 700, 파일은 600으로 제한한다. 이것은 파일 암호화를 대신하지 않는다. 원본 PDF·사진의 실제 바이너리는 이 도구가 다운로드하거나 백업하지 않는다. 보고서 본문은 운영에 준비된 복사본을 보존하며, 원본 Notion 본문의 완전한 신규 내보내기를 대신하지 않는다. 휴지통/삭제된 Notion 페이지는 포함하지 않는다.

## 데이터 보존 규칙

- 원본 Notion 속성·공지 블록을 통째로 보관한다. 지원하지 않는 서식을 평문으로 조용히 바꾸지 않는다.
- `sourcePublished`와 시각/유효성 조건을 만족하는 `effectivePublished`를 구분한다. 이관은 승인이나 공개 동작이 아니다. 비공개·미래 게시일을 유지한다.
- 기존 글 주소의 Notion ID를 `legacyPublicId`로 유지한다. 새 내부 ID의 UUIDv4 검증 때문에 주소를 바꾸지 않는다.
- 리포트의 학기·학기 내 순서·날짜·분류색·기업명·종목코드·원래 요약을 보존한다. 기존 공개 사이트의 정렬 함수를 그대로 사용한다.
- `보고서 종류`, `활동`이 비어 있으면 현재 사이트와 동일한 파생값을 함께 저장한다. 원래 속성도 별도로 보존한다.
- 회원 기수·ALUMNI/MEMBERS·회장/부회장/기장·사진·공개 상태를 유지한다. 과거 제외한 회원을 파일에서 다시 만들어 넣지 않는다.
- Drive 링크 표현이 달라도 같은 파일 ID는 같은 파일로 추적한다. 첨부/원문 역할과 여러 글의 참조를 보존한다.
- 원본 PDF SHA-256과 시험 업로더의 청크 기반 파일 식별값은 다른 알고리즘이다. `algorithm + digest + sourceVersion`을 명시하고 같은 문자열처럼 비교하지 않는다.
- 공개 준비물의 메타데이터가 최신인 경우에만 표지·페이지 묶음을 재사용 후보로 잡는다. 실제 전환 전 파일 버전/해시와 정적 파일 접근을 다시 검증한다.
- 같은 스냅샷을 반복 입력하면 중복을 만들지 않는다. 과거 수정 시점의 입력이 새 행을 덮어쓰지 않는다. 파일 준비 정보만 바뀐 경우도 갱신한다.
- 내보내기에서 빠진 항목은 자동 삭제하지 않는다. 묶음 처리 실패 시 전체 트랜잭션을 되돌린다.

## 전환 전에 구현할 항목

### 1. 파일 저장 분리

시험판의 D1 바이너리 청크 저장은 소규모 시험용이다. 기존 라이브러리를 옮기기 위해 이 상한만 높이지 않는다. 원본은 기존 Drive 파일 ID를 연결하고, 관리 DB에는 글·파일 메타데이터·수정본·참조를 저장한다. 표지와 읽기용 페이지 묶음은 기존 정적 배포 방식을 유지한다.

신규 업로드는 인증된 업로드 세션 → 재개 가능한 파일 전송 → 크기/형식/해시 검증 → 메타데이터 연결 순서로 만든다. 업로드 중단물의 유효기간, 동시 업로드 수, 파일당 상한, 저장 공간 여유, 실패 재시도를 제한한다. 새 원본 파일은 비공개로 저장하고 승인된 파일만 게시 단계에서 허용한다. 브라우저에 장기 Google 토큰을 주거나 임의 Drive ID 프록시를 열지 않는다.

Drive 쓰기 권한과 갱신 가능한 인증은 별도 연결 단계다. 기존 읽기 가능한 공유 링크가 쓰기 권한을 뜻하지 않는다. `drive.file` 범위도 기존 모든 파일에 자동 접근하지 못하므로 기존 파일 접근/소유권과 신규 앱 파일 접근을 따로 검증한다. 연결이 준비되지 않으면 가져오기는 메타데이터 시험 상태로 남긴다.

### 2. 초안과 공개본 분리

새 테이블은 기존 시험 행을 제자리 파괴하지 않는 추가 마이그레이션으로 도입한다.

| 개념 | 최소 계약 |
| --- | --- |
| 문서 | 내부 ID, 기존 공개 ID, 종류, `notion/admin` 관리 주체 |
| 수정본 | 불변 revision, 필드/본문, 원본 파일 버전, 생성 시각 |
| 게시 포인터 | 승인한 revision, 실제 게시 완료 revision, 정렬 revision |
| 자산 | provider, file ID, 해시 알고리즘/값, 크기, 상태 |
| 참조 | 문서/수정본/자산/역할. 게시본·휴지통 참조도 포함 |
| 작업 | 문서+revision 중복 방지 키, 준비/게시/실패 상태, 제한된 재시도 |

수정 중에도 기존 승인·게시본은 유지한다. PDF 교체는 새 파일을 올리고 준비가 끝난 후 승인본 포인터를 바꾼다. 기존 파일은 즉시 삭제하지 않는다. 동시 편집 시 revision이 다르면 409와 재읽기 안내를 주고 덮어쓰지 않는다.

### 3. 게시와 삭제의 관리 주체 전환

현재 공개 사이트에는 Notion 공개 상태 확인과 동기화가 남아 있다. 관리자 DB에 데이터를 넣는 것만으로 이전이 끝나지 않는다.

- 게시·본문 준비·PDF 표지/페이지 묶음·검색·사이트맵·다운로드 권한 확인에 공통 읽기 어댑터를 도입한다.
- 문서별 관리 주체를 명시한다. 관리자 관리 문서를 Notion 동기화가 덮어쓰거나 삭제하지 못하게 한다. 관리자 문서 공개 여부를 Notion에 다시 묻지 않는다.
- 대량 변환을 무조건 다시 하지 않는다. 동일 PDF의 기존 준비물을 재사용하고 바뀐 원본만 제한된 작업으로 처리한다.
- 웹훅은 빠른 접수, 중복 제거, 제한된 재시도로 처리한다. 변경이 없는 주기 작업에서는 변환·배포를 만들지 않는다.
- **이전 후 Notion을 정리하기 전에 기존 Notion→Drive 삭제 연동의 해당 문서 처리를 중지하거나 관리 주체를 확인하도록 변경한다.**
- 관리자 삭제는 먼저 휴지통, 복원 기간을 거친다. 영구 정리는 모든 공개본·초안·다른 글·회원 사진의 참조와 학회 소유/관리 폴더를 확인한 뒤 실행한다.
- 원본 삭제 실패 시 상태를 기록하고 메타데이터를 남겨 재시도한다. DB만 삭제해 고아 파일이 되거나 다른 글의 파일이 사라지지 않게 한다.

### 4. 편집 기능 호환

공지 원문에 있는 표/셀, 본문 내 PDF·일반 첨부, 소제목 단계, 콜아웃, 중첩 블록, 굵게·기울임·밑줄·취소선 등을 지원한다. 사진을 사이에 넣은 글과 첨부 다운로드를 시험한다. 지원 전에는 이관 원문을 보존하고 해당 부분의 편집을 막는다. 만료되는 Notion 첨부 주소는 파일을 안정된 저장소에 보관한 뒤 바꾼다.

회원 관리가 완성되기 전에는 전체 Notion을 폐기하지 않는다. 기수별 편집·직책·가나다 정렬·프로필 사진·공개 제외·실수 복구 기능이 별도로 필요하다.

리포트 목록은 학기/분류/상태 필터, 검색, 묶음 작업, 학기 안에서 순서 변경을 유지한다. 화면 순서 변경과 실제 공개 순서를 같은 규칙으로 검증한다.

## 시험 이전 → 전환 → 복구

1. **기준선 보관:** 코드/설정 버전, 게시 스냅샷, Notion 속성/본문, 파일 참조 목록과 체크섬을 비공개로 보관한다. PDF·첨부 실물 백업과 계정 복구 수단은 별도로 확인한다.
2. **소량 시험:** 리포트 3~5개(큰 PDF, 산업분석, 기존 준비물이 있는 글 포함), 사진 공지와 파일 첨부 공지, 비공개 공지를 별도 DB에서 시험한다. 회원은 직책/그룹/사진 사례를 검증한다.
3. **전체 시험 가져오기:** 기존 public ID를 유지하고 모두 검토 상태로 만든다. 건수·속성·순서·파일 참조·이미지·본문·공개 여부를 대조한다. 반복 실행과 실패 재시작도 시험한다.
4. **인수인계/복구 시험:** 다음 담당자의 별도 기기 패스키 등록, 기존 인증 철회, 복구 코드 교체, 새로운 DB로 백업 복구를 시험한다. 복구 코드는 코드·DB 내보내기·채팅에 넣지 않는다.
5. **최종 차이 반영:** 짧은 편집 중지 시간을 정하고 마지막 변경을 다시 대조한다. 스냅샷 생성 시각 이후의 내용이 빠지지 않게 한다.
6. **전환 승인:** 시험 결과를 확인한 후 종류별로 관리 주체를 전환한다. 이 단계 전에는 기존 운영 Worker와 Notion 게시 경로를 바꾸지 않는다. Notion 원본은 보존한다.
7. **운영 확인:** 기존 글 URL, 검색/필터/순서, PDF 첫 페이지·전체 페이지·다운로드, 공지 이미지/첨부, 회원 직책/기수, 모바일, 비공개 숨김, 무료 사용량을 확인한다.
8. **문제 시 복구:** 관리자 게시/삭제를 일시 중지하고 전환 이후 수정본·새 파일 목록을 먼저 내보낸다. 마지막 검증된 공개 스냅샷과 관리 주체를 복구한다. 새 관리 데이터를 보존·대조한다. 코드 롤백만으로 데이터까지 돌아온다고 가정하지 않는다.

## 무료 운영 확인 지점

D1 Free는 DB 하나당 500MB이며 읽기/쓰기 일일 한도가 있다. 관리자·운영 프로젝트는 계정 한도를 공유하므로 합산해야 한다. 파일 바이너리를 D1에 계속 쌓지 않는다. 무료 한도는 영구 보장으로 설명하지 않는다. [D1 제한](https://developers.cloudflare.com/d1/platform/limits/), [D1 가격/초과 동작](https://developers.cloudflare.com/d1/platform/pricing/)

Workers Free는 일일 동적 요청과 요청당 CPU 제한이 있다. 방문할 때 원문을 변환하거나 AI를 호출하는 설계를 피하고, 승인 시 준비한 정적 자료를 사용한다. [Workers 제한](https://developers.cloudflare.com/workers/platform/limits/)

Drive 저장량은 Gmail·Photos 등과 공유된다. 실제 계정 여유량을 확인해야 한다. 큰 파일에는 중단 후 재개가 가능한 업로드를 사용한다. [Google 저장 공간](https://support.google.com/drive/answer/9312312?hl=en), [Drive 업로드](https://developers.google.com/workspace/drive/api/guides/manage-uploads), [Drive 권한 범위](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

관리자 파일 용량·작업 수·보류 작업·실패 내역을 보이게 하고 한도에 가까우면 새 작업을 제한한다. 새 유료 저장소/결제 설정 없이 구현할 수 있는 범위에서 진행하되, 기존 계정 권한과 가용량을 확인하기 전에는 자동 업로드·완전 이전을 완료로 표시하지 않는다.

## 배포 전 의존성 확인

전환 코드가 준비되면 `pnpm audit`와 `pnpm audit --prod`를 다시 실행하고 기본 브랜치/시험 브랜치의 결과를 구분한다. 설치된 의존성의 경고 수와 실제 Cloudflare Worker에 포함된 경로는 다를 수 있다. 오래된 호스팅용 어댑터가 남았다면 사용처·빌드 의존성을 확인한 뒤 제거하거나 패치한다. 번들에서 발견되지 않았다는 이유만으로 모든 빌드/운영 경로가 안전하다고 판정하지 않는다. 패치 후 타입·테스트·실제 배포 빌드와 인수인계 기능을 재검증한다.
