# SMP 웹사이트 장기 운영 점검

## 현재 운영 안내 — Cloudflare (2026-10-10)

운영 사이트는 [Cloudflare 주소](https://smp-website-free.smp-website.workers.dev)입니다. Vercel 예약 실행과 Git 자동 배포는 중지했으며, 새 사이트는 기존 Vercel Blob의 정상 동작을 요구하지 않습니다. Notion·Drive의 관리 방식은 유지하고 GitHub Actions가 표지·본문을 준비합니다. 현재 한도·반영 간격·인수인계의 기준은 [README](../README.md)의 무료 운영 구조입니다.

| 증상 | 확인과 대응 |
| --- | --- |
| 새 글이나 수정이 아직 안 보임 | 제목·공개·게시일 확인 → Notion 연결의 웹훅 활성 상태 → GitHub Actions 마지막 게시 결과 확인. 표지·본문 준비는 약 15분 간격이며 예약 실행은 지연될 수 있음 |
| 목록에 대기 안내가 뜸 | Cloudflare Worker 로그·요청 사용량·Notion 장애 확인. 공개 상태가 90초 이상 확인되지 않으면 목록을 보류하도록 설계됨 |
| 상세·PDF가 함께 실패 | Notion 읽기 권한·데이터 소스·Worker Secrets 확인. 공개 여부 검사를 끄고 우회하지 않음 |
| PDF만 실패 | Drive 파일별 공유 권한·PDF 형식·외부 다운로드 제한 확인 |
| 수정 PDF의 표지가 예전 것임 | 수정본을 새 Drive 파일로 업로드하고 Notion 파일 링크 교체. 같은 파일 ID 덮어쓰기는 표지 재생성을 보장하지 않음 |
| 삭제 연동 문제 | [Drive 정리 안내](drive-cleanup.md)의 Apps Script 실행 상태 확인. 파일 원본으로 시험하지 않음 |
| GitHub 예약 게시가 멈춤 | Actions의 중지 안내 확인 후 재활성화. 장기 비활동 중지 우회용 자동 커밋은 사용하지 않음 |

평소에는 Notion 편집과 Drive 업로드만 합니다. 급한 게시에는 GitHub Actions의 `Publish CMS on the free architecture`를 `main`에서 한 번 실행합니다. 실패 원인을 확인하지 않고 반복 실행하지 않습니다. 학기 인수인계 때 Google·Notion·GitHub·Cloudflare 복구 수단, 마지막 게시 성공, 공개·비공개 전환, 대표 PDF를 확인합니다. 원본 백업과 정기 보안 업데이트가 필요하며 무료 서비스의 무중단·10년 무점검은 보장하지 않습니다.

## 이전 Vercel 운영의 점검 기록

2026년 10월 5일 기준 점검입니다. 기존 리포트 400개에 매년 20개, 공지는 매년 30개가 추가되고 최대 100명이 동시에 접속하는 조건을 사용했습니다. 10년 뒤 리포트는 약 600개, 공지는 현재 자료에 300개가 더해집니다. 데이터 개수는 충분히 관리할 수 있지만, 무료 서비스의 전송량과 외부 서비스 변경까지 10년간 무점검으로 보장할 수는 없습니다.

## 화면과 서버에서 수정한 부분

- 리포트 화면까지 내려오던 홈 배경 41,506,704바이트 사전 다운로드를 제거했습니다. 리포트 배경 원본 3,795,824바이트는 빌드할 때 최대 2,560px WebP로 변환합니다. 다른 대형 배경도 같은 방식으로 준비하며 디자인 원본은 그대로 보관합니다.
- 너비 1,024px 이상은 최대 3열, 640~1,023px는 2열, 그 이하는 1열입니다. 첫 3개 표지는 즉시 로딩하고 나머지는 지연 로딩합니다. 정보 영역은 시작과 끝이 완만한 곡선으로 600ms 동안 60px 이동하며 transform만 애니메이션합니다. 이동 공간을 카드 내부에 확보해 펼쳐진 영역까지 호버 범위가 고정됩니다. 스크롤 등장은 투명도만 바꿔 정보 영역의 이동과 중첩되지 않게 했습니다. 테두리 색상은 프레임마다 다시 그리지 않고, 처음 보이는 카드는 수화 시 숨겼다가 다시 표시하지 않습니다.
- 공개 목록과 검증된 본문은 Next.js 데이터 캐시를 60초간 재사용합니다. 캐시 생성 후 120초를 넘으면 원본을 새로 조회하며, 실패하면 오래된 내용을 계속 제공하지 않습니다. 서명된 Notion 웹훅은 공지와 리포트 캐시를 만료시킵니다.
- 상세·PDF·표지 요청은 전체 DB 대신 페이지 하나만 읽고 ID, 데이터 소스, 공개, 게시일, 휴지통 여부를 확인합니다. 이 공개 여부 확인은 지속 캐시하지 않습니다. 같은 서버의 동시 요청만 합칩니다. 본문도 처음 읽는 동시 요청을 합칩니다.
- 표지 복구는 매일 전체 자료 대신 최대 20개를 순환 점검합니다. 600개는 30일에 한 바퀴입니다. 평소 게시·수정은 웹훅이 처리하고, 누락된 표지는 요청 시에도 복구합니다. 같은 Drive 파일을 버전 교체한 경우 Notion 속성도 수정해야 빠르게 표지가 갱신됩니다.
- Notion이 긴 Retry-After를 반환하면 그보다 일찍 재시도하지 않습니다. 해당 서버에서는 기다려야 하는 동안 새 요청도 빠르게 실패시킵니다. API 실패를 비공개 전환이나 삭제로 해석하지 않습니다.
- Next.js를 16.3.8로 업데이트하고 실제로 사용하지 않는 shadcn 생성 도구와 스타일 의존성을 제거했습니다. 점검 당시 전체 의존성 보안 감사는 알려진 취약점 0건이었습니다. 이것은 미래의 취약점이나 모든 보안 결함이 없다는 보장은 아닙니다.
- GitHub Actions에서 코드 변경·PR·수동 실행 때 테스트, 고위험 이상 취약점 감사, 빌드, 타입 검사를 실행합니다. 자동 병합과 정기 알림은 설정하지 않았습니다. 이 검사 자체가 Vercel Git 배포를 차단하는 것은 아닙니다.

## 검증 결과와 한계

운영 Notion이나 Drive에 100명 부하를 보내지 않고, 로컬 프로덕션 빌드에 실제 HTTP 요청을 보냈습니다. 모의 외부 API 지연은 요청당 20ms이며, 600개 리포트와 300개 공지를 사용했습니다.

| 100개 동시 요청 | HTTP 결과 | 모의 Notion 호출 | 응답 시간 p95 |
| --- | --- | --- | --- |
| 리포트 목록 최초 조회 | 모두 200 | 목록 6회 | 1,154ms |
| 같은 목록 캐시 사용 | 모두 200 | 0회 | 633ms |
| 공지 목록 최초 조회 | 모두 200 | 목록 3회 | 520ms |
| 같은 리포트 상세 | 모두 200 | 페이지 1회, 본문 1회 | 164ms |
| 같은 소형 PDF | 모두 200 | 페이지 1회 | 44ms |

공개 해제 후 캐시가 남아 있어도 상세와 PDF는 즉시 404를 반환했고, 서명된 웹훅 뒤에는 캐시된 목록에서도 사라졌습니다. 단위·회귀 테스트 51개가 통과했습니다.

위 수치는 단일 로컬 서버 측정입니다. 실제 Vercel의 여러 인스턴스, 인터넷 지연, Google 다운로드 제한, 대용량 PDF 100개 전송 성능까지 검증한 수치가 아닙니다. 화면의 모든 기기별 FPS도 측정한 것은 아닙니다.

재검증할 때는 `tests/scale-fixture.mjs`의 안내에 따라 `SMP_TEST_FIXTURES=1`과 `NODE_OPTIONS=--import ./tests/scale-fixture.mjs`로 로컬 `next start`를 실행하고, 같은 `SMP_TEST_STATS`·`SMP_TEST_STATE` 파일을 지정해 `node tests/scale-http.mjs`를 실행합니다. 두 파일은 `/private/tmp` 또는 운영체제 임시 폴더에 둡니다. `SMP_TEST_RUN`을 새 값으로 바꾸면 다른 캐시 공간을 사용합니다. 실제 운영 환경에는 이 설정을 넣지 않습니다.

## 무료 운영의 실제 제한

2026년 10월 5일 확인한 Hobby 포함량은 Fast Data Transfer 100GB, Fast Origin Transfer 10GB입니다. 사이트 내 PDF 프록시는 PDF 전체를 Vercel 함수에서 전달하므로 두 전송량을 모두 사용합니다. 15MB PDF를 100명이 한 번씩 열면 약 1.5GB이며, 10GB는 다른 전송을 제외해도 약 660회 분량입니다. 재열람·다운로드는 추가 전송이 생길 수 있습니다. 동시 접속 횟수만으로 한 달 무료 운영 가능 여부를 판단하면 안 됩니다. [Vercel Hobby](https://vercel.com/docs/plans/hobby), [전송량 계산](https://vercel.com/docs/manage-cdn-usage)

자료실·공지 조회가 중심이면 현재 개선의 효과가 큽니다. 많은 사람이 대형 PDF를 자주 열면 PDF 배포를 전용 파일 저장소와 CDN으로 분리하는 것이 다음 구조 변경입니다. 이 점검에서 새 계정·유료 플랜·파일 저장소 이전은 진행하지 않았습니다. Google Drive의 공개 파일 다운로드 제한도 사이트 코드만으로 보장하거나 해제할 수 없습니다.

표지 Blob은 저장 1GB, 전송 10GB, 단순 작업 10,000회, 고급 작업 2,000회가 포함됩니다. CDN 캐시 적중은 단순 작업에 포함되지 않습니다. 표지 생성·복구·읽기 비용은 PDF 저장공간과 별개입니다. [Blob 포함량](https://vercel.com/docs/vercel-blob/usage-and-pricing)

Drive 용량 예시는 리포트당 평균 15MB라면 600개에 약 9GB, 공지당 이미지·첨부 합계 5MB라면 새 공지 300개에 약 1.5GB입니다. 총 10.5GB에 기존 공지, 버전 보관, 메일, 휴지통을 더해야 합니다. 평균 25MB 리포트라면 리포트만 15GB이므로 무료 15GB로 충분하다고 보장할 수 없습니다. 실제 이전 자료의 합계부터 집계합니다. [Google 저장공간](https://support.google.com/drive/answer/6374270)

## 담당자가 할 일

리포트 항목 삭제와 원본 PDF 휴지통 이동을 연동하는 선택 기능은 [Drive 삭제 연동 안내](./drive-cleanup.md)를 따릅니다. 웹사이트 코드 배포만으로 활성화되지 않으며 학회 Google 계정의 Apps Script 설치·권한 승인·예약 실행 설정이 필요합니다.

1. 평소에는 PDF 업로드, Notion 작성, 공개 체크, 사이트 확인만 합니다. PDF 수정본은 Drive 버전 관리로 교체하고 Notion 속성도 수정합니다. 순서를 바꾸려고 기존 글을 삭제하지 않습니다.
2. 큰 행사 전에는 대표 공지와 PDF를 로그아웃 상태에서 열고, Vercel Usage의 Fast Origin Transfer와 Blob 한도를 확인합니다. 월 사용량이 포함량의 70%에 가까우면 다음 행사 전에 파일 배포 구조나 플랜을 검토합니다.
3. 학기 말에는 Notion 내보내기와 PDF 원본을 학회가 통제하는 별도 저장장치에도 백업합니다. 같은 Drive 계정 안의 복사본만으로는 계정 분실을 복구할 수 없습니다. 백업에서 표 한 개와 PDF 한 개를 실제로 열어 봅니다.
4. 담당자 교체 때 Google·Notion·GitHub·Vercel의 관리자와 복구 수단을 확인하고, 예시 글 공개·비공개와 PDF 다운로드를 직접 시험합니다. 비밀번호나 토큰을 이 저장소에 기록하지 않습니다.
5. 보안 경고가 오면 즉시 확인하고, 적어도 연 1회 Node.js·Next.js 지원 상태, Notion API 버전, 무료 플랜 조건을 확인합니다. 고정 버전도 지원 종료 후에는 업데이트가 필요합니다. 10년간 갱신하지 않는 운영은 권장하지 않습니다.

## 검색 미리보기와 보안 운영 (2026-10-07)

메인 헤더 검색은 열 때 `/api/search`에서 공개 검색 목록을 한 번 받습니다. 글자를 입력할 때는 브라우저에서 최대 6개 결과만 찾습니다. 리포트·공지·회원·수상·안내 페이지를 함께 검색하고 방향키/Enter로 이동할 수 있습니다. 목록은 기존 60초 CMS 캐시를 공유하며, 브라우저 메모리에서도 최대 60초 재사용합니다. 미리보기에 잠깐 남은 항목도 상세·PDF 접근 시 현재 공개 여부를 다시 검사합니다. 검색 JSON에는 제목·설명·분류 이름·사이트 내부 경로만 있습니다.

적용한 보호:

- 모든 HTML 응답에 매번 다른 nonce를 부여한 CSP를 사용합니다. 임의 인라인 스크립트·이벤트 핸들러, 외부 프레임 삽입, 플러그인 실행을 제한합니다. PDF.js WASM과 기존 스타일은 허용합니다. nonce가 캐시된 HTML과 섞이지 않도록 페이지는 동적 렌더링하며 CMS 목록/본문 데이터 캐시는 유지합니다.
- 공통 `nosniff`, 프레임 삽입 금지, Referrer/Permissions/HSTS 헤더를 적용하고 프레임워크 식별 헤더를 제거합니다.
- 공개 표지 GET은 이미 저장된 이미지를 읽거나 용량 제한된 Google 썸네일만 받습니다. 표지 생성용 PDF 다운로드·표지 생성·Blob 쓰기는 서명된 웹훅 및 관리자 인증 동기화에서만 실행됩니다.
- PDF·표지·첨부 API는 다른 사이트의 브라우저 삽입 요청을 거부합니다. 외부 링크를 눌러 직접 방문하는 동작은 허용합니다. 메타데이터 헤더가 없는 도구나 공개 원본 URL 자체를 차단하는 장치는 아닙니다.
- 공개 API에 서버 인스턴스별 요청 제한을 적용합니다. 대학 공용 IP를 고려해 PDF 열람 6,000회, 표지 3,000회, 다운로드/첨부/검색 600회/IP/분입니다. IP는 임시 난수와 해시로 바꾸며 메모리 항목 수를 제한합니다. 여러 Vercel 인스턴스에 걸친 전역 한도나 요금 상한을 보장하지 않습니다.
- 사이트 첨부파일 리다이렉트는 알려진 Notion/Drive 파일 주소로 제한합니다. 기타 외부 자료는 목적지 도메인이 보이는 직접 링크로 제공합니다. CMS 링크는 HTTPS만 허용합니다.
- 웹훅 초기 등록은 기본적으로 닫혀 있습니다. 이미 운영 중인 Notion 웹훅은 설정 변경 없이 계속 동작합니다. 신규 설치 시에만 `report-covers.md`의 임시 설정 절차를 따릅니다. 중복 서명 이벤트는 현재 저장된 표지를 재사용합니다.
- Drive 삭제 후보가 11개 이상이면 모두 보류합니다. `drive-cleanup.md`에 복구 절차가 있습니다. Google 편집기에서 코드를 바꾸면 기존 웹 앱도 새 버전으로 배포합니다.
- GitHub 저장소에서 의존성 그래프, Dependabot 알림/보안 업데이트, 악성 패키지 알림, Secret Protection, Push protection, 비공개 취약점 제보를 활성화했습니다. CodeQL 기본 설정도 활성화해 JavaScript/TypeScript와 GitHub Actions를 push/PR/주간 일정으로 검사합니다. Secret Protection은 지원되는 패턴을 감지하는 보조 수단이며 모든 비밀 문자열을 찾아낸다는 뜻은 아닙니다.
- GitHub 검사 워크플로는 매주 자동으로 다시 실행되며 의존성 취약점을 검사합니다. Dependabot은 의존성과 GitHub Actions 업데이트 PR을 주기적으로 제안합니다. 자동 병합은 하지 않습니다. 공개 저장소의 예약 워크플로는 장기간 활동이 없으면 GitHub에서 중지할 수 있으므로 학기 인수인계 때 Actions를 확인합니다.

별도로 관리할 사항:

1. 학회 Google·GitHub·Notion 계정에 2단계 인증을 사용하고 복구 수단도 함께 인수인계합니다. 비밀번호/인증수단 입력과 변경은 담당자가 직접 수행합니다. 공유 비밀번호만으로는 전임자의 접근 종료를 보장할 수 없습니다.
2. Notion 연결은 공지·리포트 두 DB에 필요한 읽기 권한만 유지합니다. 토큰 교체 시 Vercel과 Apps Script 양쪽을 동시에 갱신해야 합니다. 단독으로 교체하면 게시·삭제 연동이 끊깁니다.
3. 운영 토큰은 Vercel Production 범위에만 둡니다. 외부 PR Preview에 운영 Notion/Blob 접근 권한을 주지 않습니다. API 토큰, 백업 코드, 비밀번호를 Notion 본문·Git·채팅으로 전달하지 않습니다.
4. 공개 해제는 원본 Drive 링크의 공유 권한이나 이미 받은 파일까지 회수하지 않습니다. 자료 회수가 필요하면 Drive 파일별 공개 권한도 변경하고 기존 공개 Blob 이미지의 잔존 여부를 확인합니다.
5. Vercel 기본 DDoS 방어는 활성 상태입니다. `/api/content/` 6,000회/IP/60초 관찰(Log) 규칙은 관리자 검토를 위한 별도 방화벽 초안으로 준비했습니다. Publish 전에는 활성 규칙이 아닙니다. 관찰 후 정상 이용에 영향이 없는지 확인하고 차단 전환을 결정합니다.

검증: `pnpm test`, `pnpm build`, `pnpm typecheck`, `pnpm test:bundles`. 로컬 운영 빌드에 `tests/scale-fixture.mjs`를 연결한 상태에서 `node tests/security-http.mjs`로 nonce·검색 공개 필드·외부 삽입 차단·PDF 다운로드·위조 웹훅 거부를 검사합니다. 실제 서비스에 부하 테스트나 대량 다운로드를 실행하지 않습니다.
