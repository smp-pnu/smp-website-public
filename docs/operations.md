# SMP 웹사이트 장기 운영 점검

2026년 10월 5일 기준 점검입니다. 기존 리포트 400개에 매년 20개, 공지는 매년 30개가 추가되고 최대 100명이 동시에 접속하는 조건을 사용했습니다. 10년 뒤 리포트는 약 600개, 공지는 현재 자료에 300개가 더해집니다. 데이터 개수는 충분히 관리할 수 있지만, 무료 서비스의 전송량과 외부 서비스 변경까지 10년간 무점검으로 보장할 수는 없습니다.

## 화면과 서버에서 수정한 부분

- 리포트 화면까지 내려오던 홈 배경 41,506,704바이트 사전 다운로드를 제거했습니다. 리포트 배경 원본 3,795,824바이트는 빌드할 때 최대 2,560px WebP로 변환합니다. 다른 대형 배경도 같은 방식으로 준비하며 디자인 원본은 그대로 보관합니다.
- 너비 1,024px 이상은 최대 3열, 640~1,023px는 2열, 그 이하는 1열입니다. 첫 3개 표지는 즉시 로딩하고 나머지는 지연 로딩합니다. 정보 영역은 시작과 끝이 완만한 곡선으로 600ms 동안 60px 이동하며 transform만 애니메이션합니다. 이동 공간을 카드 내부에 확보해 펼쳐진 영역까지 호버 범위가 고정됩니다. 스크롤 등장은 투명도만 바꿔 정보 영역의 이동과 중첩되지 않게 했습니다. 테두리 색상은 프레임마다 다시 그리지 않고, 처음 보이는 카드는 수화 시 숨겼다가 다시 표시하지 않습니다.
- 공개 목록과 검증된 본문은 Next.js 데이터 캐시를 60초간 재사용합니다. 캐시 생성 후 120초를 넘으면 원본을 새로 조회하며, 실패하면 오래된 내용을 계속 제공하지 않습니다. 서명된 Notion 웹훅은 공지와 리포트 캐시를 만료시킵니다.
- 상세·PDF·표지 요청은 전체 DB 대신 페이지 하나만 읽고 ID, 데이터 소스, 공개, 게시일, 휴지통 여부를 확인합니다. 이 공개 여부 확인은 지속 캐시하지 않습니다. 같은 서버의 동시 요청만 합칩니다. 본문도 처음 읽는 동시 요청을 합칩니다.
- 표지 복구는 매일 전체 자료 대신 최대 20개를 순환 점검합니다. 600개는 30일에 한 바퀴입니다. 평소 게시·수정은 웹훅이 처리하고, 누락된 표지는 요청 시에도 복구합니다. 같은 Drive 파일을 버전 교체한 경우 Notion 속성도 수정해야 빠르게 표지가 갱신됩니다.
- Notion이 긴 Retry-After를 반환하면 그보다 일찍 재시도하지 않습니다. 해당 서버에서는 기다려야 하는 동안 새 요청도 빠르게 실패시킵니다. API 실패를 비공개 전환이나 삭제로 해석하지 않습니다.
- Next.js를 16.3.8로 업데이트하고 실제로 사용하지 않는 shadcn 생성 도구와 스타일 의존성을 제거했습니다. 점검 당시 전체 의존성 보안 감사는 알려진 취약점 0건이었습니다. 이것은 미래의 취약점이나 모든 보안 결함이 없다는 보장은 아닙니다.
- GitHub Actions에서 코드 변경·PR·수동 실행 때 테스트, 고위험 이상 취약점 감사, 빌드, 타입 검사를 실행합니다. 자동 병합과 정기 알림은 설정하지 않았습니다. 이 검사 자체가 Vercel Git 배포를 차단하는 것은 아닙니다.

## 검증 결과와 한계

운영 Notion이나 Drive에 100명 부하를 보내지 않고, 로컬 프로덕션 빌드에 실제 HTTP 요청을 보냈습니다. 모의 외부 API 지연은 요청당 20ms이며, 600개 리포트와 300개 공지를 사용했습니다.

| 100개 동시 요청 | HTTP 결과 | 모의 Notion 호출 | 응답 시간 p95 |
| --- | --- | --- | --- |
| 리포트 목록 최초 조회 | 모두 200 | 목록 6회 | 1,154ms |
| 같은 목록 캐시 사용 | 모두 200 | 0회 | 633ms |
| 공지 목록 최초 조회 | 모두 200 | 목록 3회 | 520ms |
| 같은 리포트 상세 | 모두 200 | 페이지 1회, 본문 1회 | 164ms |
| 같은 소형 PDF | 모두 200 | 페이지 1회 | 44ms |

공개 해제 후 캐시가 남아 있어도 상세와 PDF는 즉시 404를 반환했고, 서명된 웹훅 뒤에는 캐시된 목록에서도 사라졌습니다. 단위·회귀 테스트 51개가 통과했습니다.

위 수치는 단일 로컬 서버 측정입니다. 실제 Vercel의 여러 인스턴스, 인터넷 지연, Google 다운로드 제한, 대용량 PDF 100개 전송 성능까지 검증한 수치가 아닙니다. 화면의 모든 기기별 FPS도 측정한 것은 아닙니다.

재검증할 때는 `tests/scale-fixture.mjs`의 안내에 따라 `SMP_TEST_FIXTURES=1`과 `NODE_OPTIONS=--import ./tests/scale-fixture.mjs`로 로컬 `next start`를 실행하고, 같은 `SMP_TEST_STATS`·`SMP_TEST_STATE` 파일을 지정해 `node tests/scale-http.mjs`를 실행합니다. 두 파일은 `/private/tmp` 또는 운영체제 임시 폴더에 둡니다. `SMP_TEST_RUN`을 새 값으로 바꾸면 다른 캐시 공간을 사용합니다. 실제 운영 환경에는 이 설정을 넣지 않습니다.

## 무료 운영의 실제 제한

2026년 10월 5일 확인한 Hobby 포함량은 Fast Data Transfer 100GB, Fast Origin Transfer 10GB입니다. 사이트 내 PDF 프록시는 PDF 전체를 Vercel 함수에서 전달하므로 두 전송량을 모두 사용합니다. 15MB PDF를 100명이 한 번씩 열면 약 1.5GB이며, 10GB는 다른 전송을 제외해도 약 660회 분량입니다. 재열람·다운로드는 추가 전송이 생길 수 있습니다. 동시 접속 횟수만으로 한 달 무료 운영 가능 여부를 판단하면 안 됩니다. [Vercel Hobby](https://vercel.com/docs/plans/hobby), [전송량 계산](https://vercel.com/docs/manage-cdn-usage)

자료실·공지 조회가 중심이면 현재 개선의 효과가 큽니다. 많은 사람이 대형 PDF를 자주 열면 PDF 배포를 전용 파일 저장소와 CDN으로 분리하는 것이 다음 구조 변경입니다. 이 점검에서 새 계정·유료 플랜·파일 저장소 이전은 진행하지 않았습니다. Google Drive의 공개 파일 다운로드 제한도 사이트 코드만으로 보장하거나 해제할 수 없습니다.

표지 Blob은 저장 1GB, 전송 10GB, 단순 작업 10,000회, 고급 작업 2,000회가 포함됩니다. CDN 캐시 적중은 단순 작업에 포함되지 않습니다. 표지 생성·복구·읽기 비용은 PDF 저장공간과 별개입니다. [Blob 포함량](https://vercel.com/docs/vercel-blob/usage-and-pricing)

Drive 용량 예시는 리포트당 평균 15MB라면 600개에 약 9GB, 공지당 이미지·첨부 합계 5MB라면 새 공지 300개에 약 1.5GB입니다. 총 10.5GB에 기존 공지, 버전 보관, 메일, 휴지통을 더해야 합니다. 평균 25MB 리포트라면 리포트만 15GB이므로 무료 15GB로 충분하다고 보장할 수 없습니다. 실제 이전 자료의 합계부터 집계합니다. [Google 저장공간](https://support.google.com/drive/answer/6374270)

## 담당자가 할 일

1. 평소에는 PDF 업로드, Notion 작성, 공개 체크, 사이트 확인만 합니다. PDF 수정본은 Drive 버전 관리로 교체하고 Notion 속성도 수정합니다. 순서를 바꾸려고 기존 글을 삭제하지 않습니다.
2. 큰 행사 전에는 대표 공지와 PDF를 로그아웃 상태에서 열고, Vercel Usage의 Fast Origin Transfer와 Blob 한도를 확인합니다. 월 사용량이 포함량의 70%에 가까우면 다음 행사 전에 파일 배포 구조나 플랜을 검토합니다.
3. 학기 말에는 Notion 내보내기와 PDF 원본을 학회가 통제하는 별도 저장장치에도 백업합니다. 같은 Drive 계정 안의 복사본만으로는 계정 분실을 복구할 수 없습니다. 백업에서 표 한 개와 PDF 한 개를 실제로 열어 봅니다.
4. 담당자 교체 때 Google·Notion·GitHub·Vercel의 관리자와 복구 수단을 확인하고, 예시 글 공개·비공개와 PDF 다운로드를 직접 시험합니다. 비밀번호나 토큰을 이 저장소에 기록하지 않습니다.
5. 보안 경고가 오면 즉시 확인하고, 적어도 연 1회 Node.js·Next.js 지원 상태, Notion API 버전, 무료 플랜 조건을 확인합니다. 고정 버전도 지원 종료 후에는 업데이트가 필요합니다. 10년간 갱신하지 않는 운영은 권장하지 않습니다.
