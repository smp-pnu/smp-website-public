# 검색 노출 관리

대표 주소는 `https://pnusmp.com`이며 사이트맵은 `https://pnusmp.com/sitemap.xml`이다. Google·네이버 등록 계정은 다음 운영자에게 인수인계할 학회 계정을 사용한다.

## 적용 구조

소개·커리큘럼 등 고정 페이지는 배포할 때 HTML을 미리 만든다. 리포트·공지 목록과 상세는 일반 방문자와 검색 로봇에게 같은 HTML을 제공한다. JavaScript 실행 전에도 제목, 요약, 작성자, 날짜, 준비된 Notion 본문과 링크를 읽을 수 있다. 본문이 없는 리포트에는 PDF 앞 2쪽에서 추출한 제한된 원문을 접힌 항목으로 제공한다. PDF 전체 문장을 복제하지는 않는다. JavaScript 실행 후에는 기존 검색·필터·PDF 뷰어 화면이 동작한다.

각 페이지에 제목·설명·대표 주소(canonical)·공유 이미지와 Organization, WebSite, BreadcrumbList, Report/Article 구조화 데이터를 넣는다. 없는 정보나 평점은 만들어 넣지 않는다. 검색·필터 조합은 noindex로 처리하고, 일반 목록의 페이지 번호는 별도 대표 주소로 유지한다. 존재하지 않는 주소는 실제 HTTP 404를 반환한다.

`robots.txt`는 공개 페이지의 일반 크롤링을 허용하고 API와 내부 검색 경로는 제외한다. 검색용 봇 차단을 추가하지 않았으며, 학습용 봇 허용/차단은 별도의 운영 정책이다. 시험 배포는 robots와 응답 헤더로 검색 제외한다. robots는 접근 제어 수단이 아니다.

## 공개 여부와 무료 운영

고정 페이지는 정적 파일로 제공하므로 Worker와 Notion을 호출하지 않는다. 명단은 개인정보의 오래된 복사본이 남지 않도록 정적 HTML에 저장하지 않는다. 공개 목록과 게시글 사이트맵은 기존 동기화 문서를 사용하고, 동기화 확인이 오래되면 재시도 가능한 오류로 닫는다. 상세는 현재 Notion 공개 여부를 다시 확인하며, 본문 버전이 다르면 과거 본문을 내보내지 않는다. 브라우저는 HTML에 포함된 데이터를 처음 한 번 재사용해 동일 상세 API 중복 호출을 줄인다. 기존 요청 제한은 그대로 적용된다.

검색 로봇 방문도 동적 페이지 사용량에 포함된다. 검색 노출을 위해 요청 제한이나 보안 방화벽을 해제하지 않는다. 실제 봇 접근 차단이 확인되면 공급자의 검증된 봇/IP 기준을 사용해 필요한 범위만 검토한다. 검색엔진에 이미 수집된 정보는 사이트에서 비공개로 바꿔도 즉시 삭제되지 않으며, 급한 경우 각 검색엔진의 삭제 요청 기능을 이용한다.

## 최초 등록

1. Google Search Console에 학회 Google 계정으로 로그인한다. 도메인 속성 `pnusmp.com`의 DNS 인증 또는 URL 접두어 속성 `https://pnusmp.com/`의 파일/태그 인증을 완료한다. 화면에서 실제 발급한 인증 값만 사용하고 인증 파일·레코드는 유지한다.
2. Google의 Sitemaps에 `https://pnusmp.com/sitemap.xml`을 제출하고 홈페이지 및 대표 리포트를 URL 검사한다.
3. 네이버 서치어드바이저 웹마스터 도구에 `https://pnusmp.com`을 추가한다. 학회 네이버 계정에 발급된 HTML 파일/태그로 소유 확인하고, 요청 → 사이트맵 제출에 같은 사이트맵을 제출한다.
4. 네이버 요청 → RSS 제출에는 `https://pnusmp.com/feed.xml`을 등록한다. RSS는 최신 글을 보완하며 전체 URL은 사이트맵으로 전달한다.
5. 공개 리포트를 작성할 때 기업명·종목코드·실제 제목·요약·발표일을 정확하게 작성한다. 공지는 핵심 안내를 이미지 안에만 넣지 말고 본문에도 적는다. 사이트맵은 공개 목록에서 자동 생성되므로 새 게시글마다 재등록하지 않는다.

등록은 수집과 상태 확인을 돕는 절차이며 색인·순위·AI 답변 인용을 보장하지 않는다. AI 노출만을 위한 별도 유료 서비스나 특수 스키마는 필요하지 않다.

## 검색결과 아이콘

홈페이지의 `rel="icon"`은 검색용 정사각형 PNG `/smp-search-icon.png`(192×192)를 연결한다. 승인된 흰색 S 모양에 어두운 배경을 적용해 밝은 검색결과에서도 보이게 한다. 브라우저 탭용 투명 아이콘은 유지한다. 모두 공개 정적 파일로 제공하며 별도의 Worker·Notion 호출은 없다.

로고 변경 시 `node scripts/prepare-favicon.mjs`로 파일을 다시 만들고 배포한다. 검색용 URL은 유지하고 쿼리 버전을 반복해서 바꾸지 않는다. 배포 후 이미지의 HTTP 200·PNG 형식·정사각형 규격과 robots 허용 상태를 확인한 뒤 Search Console에서 **홈페이지** 재수집을 한 번 요청한다. 이미지 URL 자체를 페이지로 색인 요청하거나 같은 요청을 반복하지 않는다. Google 반영에는 며칠~몇 주가 걸릴 수 있고 표시가 보장되지는 않는다.

## 검색 의도별 페이지 운영

관련 검색어는 아래 대표 페이지의 실제 내용으로 다룬다. 모든 조합을 제목에 나열하거나, 같은 내용의 검색어별 페이지를 복제하지 않는다. 맞춤법·띄어쓰기 변형과 동의어마다 별도 페이지를 만들 필요도 없다.

`부산대`, `부산 투자`, `부산 증권`, `SMP`, `투자 동아리`처럼 뜻이 넓은 검색어는 학회와 무관한 검색 의도도 섞인다. 순위를 약속하거나 매일 문구를 바꾸지 말고, 학회명과 지역·활동이 함께 들어가는 검색어부터 확인한다.

배포되는 제목·설명·구조화 데이터는 `free/seo/metadata.ts`, 공식 이름과 채널은 `lib/site-config.ts`에서 관리한다. 리포트 검색 제목에는 실제 CMS 기업명이 제목에 없는 경우에만 기업명·종목코드를 보충하며, 작성자가 입력한 화면 제목은 유지한다. 소개의 질문·답변과 내부 링크는 일반 방문자와 검색 로봇에게 같은 내용으로 제공한다. 이 개선에는 추가 API·유료 서비스·예약 작업이 없다.

대외 공개 시점이 정해진 뒤 운영자는 공식 카페·인스타그램 프로필과 모집 공지에 대표 주소 `https://pnusmp.com`을 일관되게 안내할 수 있다. 학교의 학회 소개에 기존 사이트 주소가 있으면 담당자에게 최신화를 요청할 수 있다. 공개 전에는 외부 채널 수정이나 홍보를 진행하지 않는다. 무관한 사이트에 링크를 뿌리거나 링크·클릭을 구매하지 않는다.

Google Search Console의 실적 → 검색결과에서 검색어와 랜딩 페이지를 함께 확인하고, 네이버 검색 리포트도 확인한다. 최초 수집·색인 후 충분한 데이터가 쌓인 기간끼리 비교한다. 노출은 있으나 클릭이 적으면 제목·설명의 정확성을, 노출 자체가 없으면 먼저 색인 상태와 콘텐츠의 유용성을 점검한다. 순위·수집 결과는 코드 배포 성공과 구분한다.

## 공식 근거 (2026-10-11 확인)

- [Google AI 검색 기능과 웹사이트](https://developers.google.com/search/docs/appearance/ai-features): 기존 SEO, 텍스트 본문, 내부 링크와 접근 가능성이 기본이며 별도 AI 파일이나 특수 스키마는 요구하지 않는다.
- [네이버 JavaScript 검색 최적화](https://searchadvisor.naver.com/guide/seo-advanced-javascript): 검색 로봇이 주요 콘텐츠를 확인할 수 있도록 구성한다.
- [OpenAI 크롤러](https://developers.openai.com/api/docs/bots): 검색용 OAI-SearchBot과 학습용 GPTBot은 별도 용도다.
- [Perplexity 크롤러](https://docs.perplexity.ai/docs/resources/perplexity-crawlers): 검색용 봇 접근을 허용할 때 공식 IP와 봇 식별 정보를 함께 검증한다.
- [Google 검색 제목](https://developers.google.com/search/docs/appearance/title-link): 페이지별로 구체적이고 간결한 제목을 사용하며 검색어를 반복 나열하지 않는다.
- [Google 검색 스팸 정책](https://developers.google.com/search/docs/essentials/spam-policies): 키워드 채우기, 유사한 진입 페이지의 대량 생성, 링크 조작을 피한다.
- [Google Organization 데이터](https://developers.google.com/search/docs/appearance/structured-data/organization): 실제 학회 이름·로고·공식 채널로 동일한 단체임을 설명한다.

검증: 단위 테스트의 HTML/JSON 이스케이프, 현재 공개 여부·본문 버전·사이트맵 신선도 검사와 로컬 Cloudflare HTTP/브라우저 확인을 사용한다. 변경 시 `pnpm test`, `pnpm typecheck`, `pnpm build:free:fixture`를 실행한다.


## 수집 안정성과 첫 화면 개선 (2026-10-11)

- `/sitemap.xml`은 정적 인덱스이며 `/sitemap-pages.xml`, `/sitemap-research.xml`, `/sitemap-notice.xml`을 가리킨다. 고정 페이지 목록은 CMS나 D1 장애에도 제공한다. 리포트와 공지 사이트맵은 각자의 동기화 상태만 검사하므로 다른 종류의 장애가 함께 전파되지 않는다.
- 게시글의 `lastmod`는 실제 Notion 수정 시각이다. 정기 배포 시각으로 전체 글의 날짜를 바꾸지 않는다. 신뢰할 수정 이력이 없는 고정 페이지에는 선택 속성인 `lastmod`를 생략한다.
- `/feed.xml`은 최신 공개 리포트·공지 중 준비가 완료된 최대 10개의 제목·작성일·요약·본문을 RSS 2.0으로 제공한다. 검색 로봇과 일반 구독자가 같은 내용을 받는다. 현재 리비전과 본문 리비전이 다르거나 동기화 확인이 5분을 넘으면 과거 본문을 내보내지 않는다. 명단은 포함하지 않는다. 리포트의 준비된 원문 발췌도 같은 공개·본문 버전 검사를 거친다.
- RSS 요청은 Notion을 호출하지 않고 D1의 준비된 내용을 사용한다. 기존 공개 요청 예산에 포함한다. 무료 실행 시간을 보호하기 위해 개별 본문 100KB·항목 20KB, 합계 160KB의 원본 JSON 예산을 적용한다. 큰 글은 본문을 자르지 않고 피드에서 제외한다. 그 글의 사이트맵·웹페이지는 그대로 유지된다. 추가 예약 작업·유료 서비스·패키지는 없다.
- 모바일 배경은 별도 1280px WebP를 사용한다. 홈페이지 배경은 1,529,912바이트에서 230,890바이트로 줄었고 데스크톱 이미지는 유지한다. 이미지 선택은 브라우저의 `picture` 기능이 담당한다.
- 화면별 JavaScript를 필요할 때 불러오며 처음 방문한 화면의 코드가 준비되기 전까지 서버 HTML을 유지한다. 홈페이지 제목을 처음에 숨기던 지연도 제거했다. PDF 렌더러는 실제 뷰어에서만 내려받는다.
- 리포트의 투자 포인트를 초기 HTML에도 제공하고, 학생 학술 자료 및 분석 시점 안내를 화면과 HTML·RSS에 동일하게 넣는다. 과거 목표주가를 현재 가격으로 오해하지 않도록 한다.

### 운영자가 유지할 내용

리포트마다 기업명·종목코드·발표일·실제 작성자·독자적인 분석 요약을 정확히 유지한다. 공지는 행사명·대상·일시·장소·지원 방법을 텍스트로 쓰고, 사진에는 내용을 설명하는 캡션을 붙인다. 공개할 근거와 분석이 없는 빈 키워드 글을 만들지 않는다. 모집 기간 등 바뀐 사실만 제때 고친다.

외부에서 학회를 확인할 수 있는 공식 소개와 링크도 중요하다. 카페·Instagram의 기존 프로필이나 학교 학회 소개를 수정할 때 사용할 문구 예시는 다음과 같다. 외부 계정 편집·연락은 운영자가 해당 채널의 권한과 최신 사실을 확인하고 진행한다.

## 공식 이름과 외부 홍보 전 운영 (2026-10-12)

2. **클릭수·노출수·평균 CTR·평균 게재순위**를 함께 켠다. **페이지** 탭에서 홈페이지 `/`가 나타나는지 확인하고, 기기 탭에서 모바일과 데스크톱을 구분한다. 검색어 변형은 `부산대학교 SMP`, `SMP 부산대`, 공식 학회명 등을 각각 보거나 정규식 `(?i)부산(대|대학교).*smp|smp.*부산(대|대학교)`로 묶는다.
