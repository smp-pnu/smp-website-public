# PDF 관리자 온라인 시험판

`feature/pdf-admin-cloud-trial-20261025`의 별도 Worker `smp-pdf-admin-trial`과 별도 D1만 사용한다. 운영 main, pnusmp.com, 운영 Worker, Notion, Drive와 연결하지 않는다. ‘시험 승인’은 시험 초안의 상태만 바꾼다. 로컬 아이디·비밀번호 서버도 유지한다.

## 로그인

Zero Trust 가입·카드 청구 동의 없이 WebAuthn 패스키로 로그인한다. SimpleWebAuthn의 검증을 사용하며 RP ID를 `admin.pnusmp.com`, HTTPS origin을 `https://admin.pnusmp.com`으로 고정한다. ES256, 사용자 확인 필수, discoverable credential, attestation none이다. 생체정보·개인 키는 기기/패스키 제공자에 있고 서버에는 공개 키만 저장한다. 외부 인증서 검증·메타데이터 서비스를 호출하지 않는다.

최초 1회는 임의의 256비트 초기 설정 키로 패스키 등록을 시작한다. 설정 키의 SHA-256만 시험 Worker Secret에 둔다. 등록 완료 후 DB의 초기화 상태가 재등록을 차단한다. 추가 기기는 로그인 후 ‘로그인 기기 관리’에서 등록한다(최대 5개). 해제한 키의 로그인 세션은 즉시 무효다. 마지막 패스키는 삭제할 수 없다. 패스키를 동기화할지는 사용자 기기 설정에 따른다.

최초 등록과 복구 완료 시 새로운 256비트 복구 코드를 화면에서 한 번만 제공한다. 관리자는 파일을 내려받아 별도 안전한 곳에 보관해야 한다. 분실 시 로그인 화면의 ‘복구·인수인계’에서 복구 코드를 입력하고 새 패스키 등록을 완료한다. 하나의 DB 트랜잭션으로 기존 패스키·세션을 해제하고 복구 코드를 교체한다. PDF와 초안은 유지된다. 기존 코드는 재사용할 수 없다. 패스키와 복구 코드를 모두 잃으면 학회 Cloudflare 계정 관리자의 별도 복구 작업이 필요하다.

챌린지는 5분·1회용이고 HttpOnly 흐름 쿠키에 결합된다. 로그인은 서버 저장 세션 + HMAC 서명 쿠키이며 30분 미사용/최대 8시간 후 만료된다. Cookie는 Secure·HttpOnly·SameSite=Strict·__Host 접두사를 사용한다. 변경 요청은 정확한 Origin과 세션 CSRF를 검증한다. 서명이 없는 자료 요청은 DB 조회 전에 차단한다. 공개 가입·비밀번호 인증·이메일 발송은 없다. 정적 로그인 화면은 공개지만 초안/PDF/표지는 인증 후에만 받을 수 있다. 검색 색인은 차단한다.

## 저장 흐름

브라우저가 PDF를 분석해 표지와 입력 후보를 만든다. PDF 원문과 표지는 256KiB 조각으로 순차 전송하고 서버는 실제 조각 해시·완성 매니페스트를 검사한다. 완성 전 업로드는 목록에 나오지 않는다. 새로고침해도 완성된 자료는 별도 D1에 남는다. 다운로드 시 브라우저는 병렬 3개로 조각을 받고 내용을 검증한다.

온라인 관리자 클라이언트는 PDF 분석기를 포함한 단일 JavaScript 번들을 사용한다. 배포 후 열려 있던 탭에서 삭제된 이전 해시의 분석기 조각을 요청하지 않도록 하는 구성이다. 빌드는 별도 지연 로딩 JS 조각이 없는지와 번들 크기(원문 900KB/압축 270KB 이내)를 확인한다. PDF.js Worker·폰트 등 정적 리소스는 필요한 시점에 기존 동일 출처 경로에서 읽는다. 화면 파일은 no-store이며 자동 새로고침으로 편집을 잃게 하지 않고, 네트워크·모듈 오류에는 저장 자료가 보존된다는 안내와 수동 새로고침 방법을 표시한다. 이 구성은 관리자 시험판에만 적용한다.

Worker는 PDF 전체 구조 검사나 표지 재인코딩을 하지 않는다. 헤더·끝 표시·바이트 수·내용 해시·표지 크기를 검증하며, 페이지 수와 추출 내용은 브라우저 분석 결과를 관리자가 검토한다. 원본은 첨부파일로 내려받으며 임의 HTML을 실행하지 않는다. 업로드는 1건만 예약할 수 있고 30분 후 다음 작업에서 정리된다. 영구 삭제하면 파일 조각도 같은 트랜잭션으로 제거한다.

## 무료 한도와 경계

2026-10-25 공식 문서 기준 Workers Free는 계정 전체 하루 10만 요청·호출당 CPU 10ms, D1 Free는 하루 500만 행 읽기·10만 행 쓰기·계정 저장 5GB·DB당 500MB다. 정적 파일은 Worker를 거치지 않는 자산 경로를 사용한다. 플랫폼 계정 총량은 기존 운영 사이트와 공유한다.

| 시험판 자체 제한 | 값 |
| --- | --- |
| PDF 파일당 | 32MiB / 브라우저 분석 120페이지 |
| 총 저장 | 200MiB / 50개, 휴지통·예약 업로드 포함 |
| 표지 | 1MiB 이하 정적 WebP 또는 JPEG, 각 변 최대 2048px |
| 인증된 자료 API | 전체 하루 5,000회, 분당 600회 |
| 공개 인증 POST | Cloudflare 바인딩으로 요청자·단계별 분당 20회, 초과 요청은 D1 접근 전 거부. 지역별 근사 한도이며 공격 트래픽 전체에 대한 무료 사용량 보장은 아님 |
| 동시 업로드 | 1건, 여러 파일은 순차 처리 |
| AI 입력 보완 | 전체 하루 최대 10회, 실패 포함, UTC 자정(한국 오전 9시) 초기화 |

200MiB 원문은 base64 저장 시 약 267MiB다. 메타데이터·인덱스 여유를 두되 실제 D1 크기도 확인한다. 소규모 관리자 시험용이며 수백 개 PDF를 쌓는 운영 저장소가 아니다. 악의적인 반복 접근은 인증 한도 때문에 로그인을 일시 막을 수 있고, 무인증 요청도 Workers 계정 요청 수를 사용한다. 앱 제한이 외부 장애·공격·다른 서비스의 사용량까지 막지는 않는다. 이상 사용 시 시험 Worker를 중단한다.

이 구성은 Workers/D1/Workers AI Free를 사용하고 R2·Access·유료 전환·주기 작업을 추가하지 않는다. 무료 한도 초과 시 실패/일시 중단될 수 있으며 자동 과금이 아니라 한도 내 사용이 전제다. 운영 전에는 별도 파일 저장 어댑터, 백업·복원, 기기 인수인계를 검증한다.

## AI 입력 보완

온라인 시험판의 새 PDF 등록과 ‘입력 후보 다시 추출’에서 기본 추출 후 Cloudflare Workers AI의 `@cf/meta/llama-3.3-70b-instruct-fp8-fast`를 호출한다. 앞 3쪽에서 추출한 텍스트만 합계 12,000 UTF-8 바이트 이내로 전송하며, 이메일과 흔한 전화번호 형식을 먼저 가린다. 이 처리는 완전한 익명화를 보장하지 않으므로 전송 안내를 관리자 화면에 표시한다. PDF 파일·표지 이미지는 모델에 보내지 않는다. 로컬 전용 관리자와 운영 사이트에는 이 호출을 연결하지 않는다.

기업명·6자리 종목코드·제목·발표일·목표연도·목표주가·상승여력·작성팀·Not Rated를 구조화된 후보로 요청한다. 각 후보에는 원문 인용과 페이지가 필요하다. 서버와 클라이언트가 인용 존재 및 값 일치를 검사하고, 기업명과 종목코드는 같은 페이지의 표기 또는 기존 기업표와 대조한다. 비교기업 오인·모델 오류 가능성은 남으므로 자동 승인하지 않는다. 빈 필드와 파일명으로 된 임시 제목만 보완하고, 값이 충돌하면 기존 값을 유지하고 확인 안내를 남긴다. 이미 저장한 초안의 ‘다시 추출’은 기존 확인 절차에 따라 편집값을 새 후보로 교체한다.

로그인·Origin·CSRF 확인 후 서버에서 하루 10회만 허용하며 실패도 횟수에 포함한다. 입력 프롬프트는 직렬화 기준 18,000 UTF-8 바이트, 출력은 최대 1,200토큰이고 모델 재시도·대체 모델·AI Gateway는 사용하지 않는다. 동시 요청은 DB 예약으로 중복 호출을 막는다. 같은 PDF 해시·같은 추출 텍스트 결과는 7일간 재사용하고 만료 데이터는 다음 추출 요청에서 정리한다. 캐시는 최대 100건이며 원문 전체 대신 검증된 후보·짧은 근거만 저장한다. 원문이나 모델 응답을 애플리케이션 로그로 남기지 않는다.

AI 미연결·오류·한도 도달·30초 응답 제한 시 기본 추출값으로 PDF 등록을 계속한다. 텍스트가 없는 스캔 PDF는 AI OCR을 실행하지 않고 수동 확인을 안내한다. 모델 출력은 저장 전 검토할 후보이며 투자 판단이나 보고서 요약을 생성하지 않는다.

2026-10-26 공식 기준 Workers AI Free는 계정 전체 하루 10,000 Neurons이며 초과 호출은 실패하고 더 사용하려면 유료 전환이 필요하다. 앱의 10회·입출력 제한은 이 예산에 여유를 두기 위한 보수적 설정이며 실제 사용량은 모델 토큰 수와 계정 내 다른 AI 작업에 영향을 받는다. 무료 플랜을 변경하지 않고 AI 오류가 파일 등록까지 막지 않게 한다. 모델의 실제 정확도·지연 시간은 실데이터 추론을 별도로 확인해야 한다.

## 배포·인수인계

Git 제외 파일 `.smp-tools/admin-cloud-target.json`에는 시험 `databaseId`만 둔다. `SESSION_SIGNING_KEY`(256비트 난수)와 `SETUP_TOKEN_HASH`는 정확히 이 Worker의 Secrets에만 설정한다. 설정 키 원문·복구 코드·세션·PDF는 Git/로그에 넣지 않는다. 스키마는 시험 D1에만 적용한다.

`pnpm build:admin:cloud`, `node scripts/admin-cloud.mjs dry-run`, `pnpm deploy:admin:cloud` 순서다. 배포 도구는 시험 Worker·계정·DB ID/원격 이름을 검증하고 운영·기존 미리보기 DB 및 승인된 `admin.pnusmp.com` 이외의 도메인/스케줄/다른 서비스 연결을 거절한다. 운영으로 자동 병합하거나 배포하는 워크플로는 추가하지 않는다.

다음 관리자에게는 새 기기의 패스키를 먼저 등록하고 로그인 시험 후 이전 키를 해제한다. 복구 코드를 공유하는 경우 그 코드는 계정 전체를 교체할 수 있는 비밀이므로 안전하게 전달한다. 복구가 완료되면 기존 코드 대신 새 코드를 보관한다. 중단 시 시험 Worker만 비활성화하고 D1은 확인 없이 삭제하지 않는다.

## 검증

`pnpm test`, `pnpm typecheck`, `pnpm build:admin:cloud`, `pnpm test:admin:cloud`. 마지막 명령은 실제 workerd·로컬 임시 D1에서 암호학적으로 유효한 WebAuthn 등록/로그인, 최대 32MiB PDF 업로드·다운로드 바이트 일치, 무인증 차단을 검사한다. 선택적으로 실제 로컬 PDF 경로를 받는다. 테스트 인증기는 테스트 코드에만 있고 배포에는 포함되지 않는다.

테스트는 위조/만료 세션, 다른 origin, 사용자 확인 없는 증명, 잘못된 서명, 챌린지 재사용, 기기 추가·해제, 복구 코드 교체, CSRF, 부분 업로드·용량 제한·상태 충돌·휴지통을 포함한다. 사용자 패스키 등록 및 실제 온라인 PDF 저장은 배포 후 별도로 확인한다. 로컬 실행 시간은 Cloudflare CPU 시간이나 인터넷 전송 속도의 측정값이 아니다.

## 관리자 화면과 별도 주소

2026-10-25 화면은 콘텐츠 목록과 상세 편집을 분리했다. 리포트 목록에는 검색·상태·정렬을 모으고, 저장되지 않은 편집은 메뉴 이동 때 확인한다. 로그인·인수인계는 같은 관리자 메뉴 안에서 안내한다. 대형 소개 문구, 장식용 지표와 애니메이션은 사용하지 않으며 시스템 글꼴을 사용한다. 클라이언트의 정렬과 화면 전환에 서버 API를 추가하지 않았다.

정식 운영은 `admin.pnusmp.com`처럼 공식 홈페이지와 별도 배포·호스트를 쓰고, 필요하면 공식 홈페이지 하단에 관리자 링크만 두는 구성을 권장한다. 같은 호스트의 `/admin`도 가능하지만 운영 사이트의 배포와 접근 제어가 더 강하게 묶인다. 주소를 분리하는 것 자체가 인증을 대신하지 않으며 자료 API의 인증은 유지해야 한다. 2026-10-25 사용자 요청으로 `admin.pnusmp.com`을 기존 시험 Worker에 연결한다. 루트·www의 운영 Worker 연결과 운영 사이트 링크는 변경하지 않는다. 기존 workers.dev 주소의 정적 화면은 새 주소로 이동하며 API는 차단한다. 주소 이동에는 쿠키·쿼리·초기 설정 키를 전달하지 않는다.

기존 workers.dev 패스키는 새 호스트에서 사용할 수 없다. 새 주소의 `/#handoff`에서 사용자가 보관한 복구 코드를 직접 입력하고 새 패스키를 등록한다. 기존 DB의 초기화 상태는 유지되어 초기 설정 키로 재등록할 수 없다. 유효한 새 패스키 등록이 완료될 때만 기존 패스키·세션을 교체하며 PDF와 초안의 바이트는 유지한다. 새 복구 코드를 보관한 뒤 로그아웃·로그인까지 확인한다. 전환 실패 시 기존 Worker 버전으로 되돌릴 수 있으며, 등록 성공 후에는 새 복구 코드로 다시 복구해야 한다.

한 학기당 관리자 1명인 인수인계에는, 다음 담당자가 자신의 기기에서 기존 복구 코드로 패스키를 교체하는 현재 절차를 쓸 수 있다. 새 등록이 완료되기 전에는 기존 권한이 유지되며, 완료 순간 기존 패스키·세션과 복구 코드가 무효가 된다. 다음 담당자가 새 복구 코드를 직접 보관한다. 단순히 새 패스키를 추가하고 이전 키만 해제하는 방식은 이전 담당자가 알고 있는 복구 코드까지 폐기하지 않으므로 완전한 인수인계로 설명하지 않는다. 실제 인수인계나 기존 관리자 권한 해제는 이번 디자인 작업에서 실행하지 않았다.

## 인증 관리 보완

패스키 추가·해제 및 Drive 키 교체는 기존 패스키의 사용자 확인을 다시 받는다. 재인증 결과는 같은 세션·대상 작업에만 유효하고 2분 이내 한 번 사용한다. 새 기기 등록 증명도 시작한 세션에 묶는다. 성공한 보안 변경은 비밀정보 없이 작업 종류·시각만 최근 90일/200건 중 작은 범위로 보관한다. 인증 보호 바인딩이 누락되면 로그인 기능은 설정 오류로 닫힌다. 관리자 배포 설정에 해당 바인딩이 포함돼야 한다.
