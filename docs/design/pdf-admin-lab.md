# PDF 관리자 로컬 시험판

브랜치: `feature/pdf-admin-lab-20261024`. [전체 전환 설계](admin-cms.md)의 첫 단계다. 현재 사이트와 별도의 앱으로 실행하며 운영 배포 대상에 포함하지 않는다.

## 실행

저장소에서 `pnpm dev:admin`을 실행하고 `http://127.0.0.1:3012/`를 연다. 빌드 결과는 `pnpm build:admin` 다음 `pnpm preview:admin`으로 확인한다. 같은 포트에 두 서버를 동시에 실행하지 않는다.

화면의 **예시 PDF 2개로 테스트**를 누르거나 PDF 파일을 선택한다. 예시는 가상 수치가 들어 있는 합성 문서다. 실제 기업 분석이나 투자 의견이 아니다.

## 확인할 흐름

1. PDF를 선택하면 파일 형식·크기를 검사하고 SHA-256 해시로 같은 파일을 찾는다.
2. 처음 추가하는 파일은 PDF.js로 첫 3페이지의 텍스트와 첫 페이지 표지를 준비한다.
3. 표지에서 기업명과 함께 식별되는 소개 문구가 있으면 제목 후보로 사용하고, 불확실하면 파일명을 사용한다. 확인 가능한 기업 정보·날짜·작성팀·목표연도·목표주가·상승여력만 입력 후보로 넣는다. 회사 정보는 저장소의 기존 기업표이며 실시간 조회가 아니다. 학기나 불명확한 날짜는 추측하지 않는다.
4. 입력을 수정하고 **초안 저장**을 누른다. 자동 입력 근거에서 원문 페이지와 출처를 확인할 수 있다.
5. 원문 확인 체크 후 **검토 완료 · 시험 승인**을 누른다. 실제 사이트에는 게시하지 않는다.
6. 승인 후 내용을 수정해 저장하면 검토 대기로 돌아간다. 같은 PDF를 다시 추가하면 기존 초안을 찾는다.
7. 새로고침하면 저장된 목록이 복원된다. 휴지통 이동과 복원도 브라우저 안에서만 동작한다.
8. 자동 입력 근거의 **입력 후보 다시 추출**은 확인 후 편집값을 새 후보로 교체한다. 승인도 해제되며 원본 PDF와 표지는 재사용한다. PDF 처리 중에는 다른 초안을 편집할 수 없어 자동 선택과 편집이 충돌하지 않는다.

‘게시물 미리보기’는 입력 정보·요약·표지를 보여 준다. 전체 PDF는 ‘원본 PDF’로 내려받아 확인한다. 새 수정본을 기존 글에 연결하는 버전 교체, 전체 페이지 게시 변환, 원격 저장은 다음 단계다.

## 시험 범위와 무료 운영

| 항목 | 현재 시험판 |
| --- | --- |
| 저장 | 이 브라우저의 IndexedDB. PDF·표지·초안을 따로 저장 |
| 외부 연결 | 없음. Notion·Drive·D1·GitHub API 및 AI 호출 없음 |
| 로그인 | 없음. 로컬에서만 실행하는 시험 화면이며 인증 구현으로 간주하지 않음 |
| 승인 | 로컬 상태만 기록. 운영 게시 없음 |
| 파일 한도 | PDF 32 MiB, 120페이지, 선택 한 번에 5개 |
| 저장 한도 | PDF와 표지를 합해 200 MiB, 휴지통 포함 50개 |
| 분석 한도 | 파일별 30초, 순차 처리, 텍스트 최대 첫 3페이지 |
| 표지 | 가로 최대 1200px, 최대 200만 픽셀 WebP |

새 외부 의존성을 설치하지 않고 기존 PDF.js·React·Vite를 사용한다. 운영 Worker·클라이언트·DB·배포 워크플로에는 이 앱을 추가하지 않는다. 빌드 산출물은 `dist/admin-lab/`이며 운영 산출물과 분리한다. localhost 바인딩과 외부 통신을 제한하는 CSP를 사용한다. 개발 서버는 환경 파일을 읽지 않는다.

브라우저 데이터를 지우거나 다른 브라우저·다른 주소로 접속하면 기존 초안이 보이지 않을 수 있다. 이 저장소는 운영 백업이 아니다. 원본은 별도로 보관한다. 스캔 자료의 OCR, AI 작성, 네이버 로그인, Drive 업로드, 운영 게시 연결은 아직 구현하지 않았다.

## 코드 경계

- `admin-lab/model.ts`: 크기 제한, 필수 검토 항목, 승인·수정·휴지통 상태 규칙.
- `admin-lab/extract.ts`: 원문 후보 추출과 출처 기록. 기존 기업 식별 규칙을 재사용.
- `admin-lab/pdf.ts`: PDF 헤더·해시 확인, 지연 로딩한 PDF.js 분석, 표지 생성·취소·자원 정리.
- `admin-lab/storage.ts`: IndexedDB 트랜잭션. 중복 방지·용량 계산·버전 충돌 검사를 같은 쓰기 트랜잭션에서 처리.
- `admin-lab/use-lab.ts`: 순차 입력과 화면 상태. 창에 다시 포커스가 왔다고 저장 전 편집 내용을 덮어쓰지 않음.
- `admin-lab/app.tsx`, `editor.tsx`: 목록·업로드·검토·미리보기.
- `admin-lab/confirm.tsx`: 편집값 교체·삭제 확인 대화상자와 키보드 포커스 처리.
- `scripts/admin-lab.mjs`, `admin-lab/vite.config.ts`: 로컬 실행과 별도 빌드. 배포 명령 없음.

## 검증과 다음 단계

검사: `pnpm typecheck`, `pnpm test`, `pnpm build:admin`.

2026-10-24 로컬 검증에서 타입 검사·275개 테스트·별도 빌드가 통과했다. 브라우저에서는 합성 PDF 2개의 실제 분석·표지 생성·자동 입력, 파일 선택 업로드, 새로고침 복원, 같은 PDF 재사용, 승인 뒤 수정에 따른 승인 해제, 휴지통 복원, 손상 파일 거부를 확인했다. 390px 모바일 화면의 가로 넘침도 없었다. 관측한 정상 흐름에서 외부 HTTP 요청은 없었다.

기존 인바디(27쪽), 한국콜마(24쪽), 효성중공업(25쪽) PDF 사본도 로컬에서 분석·표지 생성·재추출을 확인했다. 이때 발견한 PDF 텍스트의 숫자 사이 공백 문제는 완전한 쉼표 묶음으로 읽도록 수정하고 회귀 테스트를 추가했다. 인바디는 소개 문구와 날짜도 추출됐지만, 다른 자료의 불확실한 소개 문구·날짜·목표연도는 수동 확인이 남는다. 자동 입력은 검토 후보이며 정확성을 보장하는 자동 게시 기능이 아니다.

배포 전에는 별도 시험 서버 인증, 제한된 Drive 연결, 승인된 버전만 받는 게시 작업, 데이터 복구를 구현·검증해야 한다. 현재 로컬 호스트 검사와 CSP를 관리자 인증 대신 사용해서는 안 된다. 이 브랜치를 `main`에 병합하거나 사이트에 배포하는 것은 사용자 확인 이후 별도 단계다.
