# SMP-Website
SMP 공지사항 및 PDF 리포트 웹사이트 — Notion CMS, GitHub 동기화, Vercel 배포

2026-10-02 전달받은 배포 소스를 가져온 Next.js App Router 프로젝트입니다. 웹사이트 코드는 GitHub에서 관리하고, 공지와 리포트는 Notion에서 작성합니다. Notion 글을 수정할 때마다 GitHub 커밋이나 재배포를 할 필요는 없습니다.

- 운영 사이트: [smp-pnu.vercel.app](https://smp-pnu.vercel.app)
- 운영 코드: [smp-pnu/smp-website-public](https://github.com/smp-pnu/smp-website-public), `main` 브랜치
- 배포 관리: [Vercel SMP / smp-pnu](https://vercel.com/smp-07ee/smp-pnu), Hobby

기존 비공개 저장소는 원본 보관용입니다. 앞으로 웹사이트 코드 수정은 이 공개 저장소에서 진행합니다. 공개 저장소에는 내부 편집 문서, 실제 연결 정보와 원본 Git 이력을 포함하지 않았습니다.

## 콘텐츠 관리

학회 운영진이 Notion에서 공지와 리포트를 작성합니다. 관리 페이지와 DB 주소, 연결 토큰 및 실제 데이터 소스 ID는 비공개 인수인계 자료와 서버 환경변수로 관리합니다.

각 DB에 비공개 작성 예시가 있습니다. 복제한 뒤 제목, 게시일, 분류, 작성자, 요약과 본문을 작성합니다. PDF는 **학회 구글 드라이브에 업로드하고 파일 공유 주소를 `외부 링크`에 입력**합니다. 검토 후 `공개`를 체크하면 웹에 게시됩니다. 공지의 `상단 고정`은 최신순보다 우선합니다.

### PDF 게시: 구글 드라이브 + Notion

Notion 무료 요금제의 파일당 5MB 제한을 피하기 위해 PDF는 구글 드라이브에 보관합니다. Google 무료 저장공간은 Gmail·Drive·Photos 합계 15GB입니다. [Notion 파일 제한](https://www.notion.com/help/images-files-and-media), [Google 저장공간 안내](https://support.google.com/googleone/answer/9004014).

1. 학회 Google 계정으로 로그인하고 `SMP 리포트 PDF` 폴더에 PDF를 업로드합니다. 폴더 주소는 비공개 Notion 관리 페이지에 있습니다.
2. 공개할 **파일**의 `공유 → 일반 액세스`를 `링크가 있는 모든 사용자 / 뷰어`로 설정하고 파일 링크를 복사합니다. 폴더 주소 대신 개별 PDF 주소를 사용합니다.
3. 노션 글의 `외부 링크`에 복사한 주소를 넣습니다. 드라이브 파일을 다시 Notion `첨부파일`에 업로드할 필요는 없습니다.
4. 제목·게시일을 입력하고 `공개`를 체크합니다. 사이트 상세의 `첨부 자료`에 PDF 뷰어와 `PDF 다운로드` 버튼이 자동으로 표시됩니다. 페이지 이동·확대와 다운로드를 확인합니다.
5. 로그아웃한 브라우저에서도 사이트에서 PDF가 표시되는지 확인합니다. 오류가 나오면 PDF 파일인지, 파일 링크가 맞는지, 해당 파일이 `링크가 있는 모든 사용자 / 뷰어`인지 확인합니다.

방문자는 드라이브 화면으로 이동하지 않고 사이트에서 PDF를 읽거나 다운로드합니다. 드라이브 **폴더는 비공개**로 유지하고 게시할 PDF 파일만 공유하세요. 이 방식은 드라이브 전체를 공개하지 않지만, 공유한 PDF 자체를 비공개로 만드는 기능은 아닙니다. 원본 파일 주소를 아는 사람은 그 파일에 접근할 수 있습니다.

노션 `공개`를 해제하면 사이트에서 글이 숨겨집니다. PDF 자체의 접근도 중단하려면 드라이브 파일의 일반 액세스를 `제한됨`으로 별도 변경합니다. 개인 계정 소유의 파일 대신 학회 계정으로 업로드한 파일을 사용하고, 다음 담당자에게 학회 Google 계정의 접근·복구 수단도 인계합니다. [Google 파일 공유 안내](https://support.google.com/drive/answer/2494822?hl=ko).

**공개 조건:** 제목이 있고, 공개가 체크되었으며, 게시일이 현재 또는 과거인 글만 표시합니다. 게시일이 없거나 미래이면 숨깁니다. 날짜만 지정하면 한국 시간 자정부터 표시합니다. 공개 해제·삭제 후 새 웹 요청에서는 제외됩니다. 이미 열린 화면이나 이미 내려받은 파일까지 회수하지는 않습니다.

| 속성 | Notion 타입 | 용도 |
| --- | --- | --- |
| 제목 | 제목 | 필수 |
| 공개 | 체크박스 | 기본 비공개 |
| 게시일 | 날짜 | 필수, 미래 날짜 예약 게시 |
| 분류 | 선택 | 목록 분류 필터 |
| 요약 | 텍스트 | 목록·검색·상세 소개 |
| 작성자 | 텍스트 | 이름 또는 팀 |
| 첨부파일 | 파일과 미디어 | PDF 등 여러 파일 |
| 외부 링크 | URL | 구글 드라이브 PDF 파일 공유 주소 또는 외부 원문 |
| 상단 고정 | 체크박스 | 공지 DB에만 사용 |

위 속성 이름은 코드와 일치해야 합니다. 분류 옵션은 자유롭게 추가할 수 있습니다.

## 최초 연결

기존 학회 환경에 연결할 때는 비공개 인수인계 자료의 연결 정보를 사용합니다. 새 환경에서만 아래 설정을 진행하고, 기존 `.env.local` 파일을 덮어쓰지 마세요. 토큰을 재발급하면 운영 서버의 값도 함께 교체해야 합니다.

1. 학회 Notion의 `설정 → 개발자 → 개발자 도구 열기 → 신규 연결`에서 `SMP Website`라는 API 토큰 방식 연결을 만들고 콘텐츠 읽기 권한만 줍니다. 삽입·수정·댓글·사용자 정보 권한은 웹사이트에 필요하지 않습니다. [Notion 개발자 도구](https://www.notion.so/profile/integrations).
2. Notion 관리 페이지의 `연결`에서 해당 Integration을 추가합니다. 하위 공지·리포트 DB에도 접근 가능한지 확인합니다.
3. `.env.example`을 `.env.local`로 복사하고 `NOTION_TOKEN`을 입력합니다. 두 데이터 소스 ID도 입력합니다. DB 주소의 ID와 데이터 소스 ID는 다릅니다.
4. 배포 서비스에도 같은 세 환경변수를 등록한 후 배포합니다. 토큰을 GitHub, Notion 본문, 채팅 또는 `NEXT_PUBLIC_` 변수에 넣지 마세요.

Codex의 Notion 앱 연결은 웹 서버에서 사용할 API 토큰을 대신하지 않습니다. 토큰이 없는 상태에서도 빌드는 가능하고, 방문자 화면에는 빈 목록이 나옵니다. 실제 DB 연결 상태는 첫 게시 글로 별도 확인해야 합니다.

```sh
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
# .env.local에 NOTION_TOKEN 입력
pnpm dev
```

Node.js 22 이상, package.json에 지정한 pnpm을 사용합니다.

## 배포

2026-10-03 Vercel Hobby 배포를 완료했습니다. Vercel의 GitHub 앱은 이 공개 저장소 하나에만 접근하며, `main`에 코드를 푸시하면 자동 배포됩니다. Notion 편집은 재배포 없이 다음 웹 요청에 반영됩니다.

Vercel Hobby는 비공개 GitHub 조직 저장소의 Git 연동 배포를 지원하지 않고 비상업적 개인 사용으로 제한됩니다. 운영 목적이나 과금 정책이 달라지면 이용 조건을 다시 확인합니다. [Vercel Git 배포 조건](https://vercel.com/docs/git), [Hobby 사용 조건](https://vercel.com/docs/limits/fair-use-guidelines).

Vercel을 선택하면 배포할 GitHub 저장소를 Import하고 Framework를 Next.js로 선택합니다. 저장소 루트를 프로젝트 루트로 사용하고 다음 환경변수를 Production과 필요한 Preview 환경에 설정합니다. 다른 호스팅을 선택하면 해당 서비스에 맞는 빌드·배포 설정과 검증이 추가로 필요합니다.

```text
NOTION_TOKEN=(읽기 전용 Integration 토큰)
NOTION_NOTICES_DATA_SOURCE_ID=(공지 DB 데이터 소스 ID)
NOTION_REPORTS_DATA_SOURCE_ID=(리포트 DB 데이터 소스 ID)
```

이 앱은 서버에서 Notion API를 호출하므로 정적 GitHub Pages 배포 대상이 아닙니다. 배포 후 공개 글 한 건으로 공지 목록→상세→첨부파일과 리포트→홈 최신 리포트→통합 검색을 확인하고, 공개를 해제한 뒤 새로고침하여 사라지는지 확인합니다.

현재 세 환경변수는 **Production 전용 Sensitive 값**입니다. Preview에는 학회 Notion 연결이 없으므로 빈 목록이 표시될 수 있습니다. 토큰은 Vercel에서 공개하지 말고, 교체가 필요할 때 새 토큰을 등록한 뒤 재배포합니다.

## 담당자 인수인계

1. 학회 Notion의 `SMP 웹사이트 관리`에서 공지·리포트 DB와 비공개 작성 예시를 확인합니다. 예시를 복제해서 글을 작성하고, 제목·게시일과 `공개` 체크를 확인합니다.
2. 학회 Notion·Google 계정의 로그인·복구 수단을 다음 담당자가 관리할 수 있게 이전하고, GitHub 조직 관리자 권한과 Vercel SMP 프로젝트 접근을 확인합니다. Google Drive의 `SMP 리포트 PDF` 폴더에 업로드·공유할 수 있는지도 확인합니다. 비밀번호나 복구 코드는 이 저장소나 공개 문서에 기록하지 않습니다.
3. 다음 담당자가 직접 테스트 글을 공개하여 사이트 목록·상세·검색을 확인하고 다시 비공개로 전환합니다. 실제 학회 PDF를 처음 올릴 때는 사이트의 첨부 자료 링크까지 열어 확인합니다.
4. 일상적인 공지·리포트 수정은 Notion에서 처리합니다. 메뉴·소개·회원 정보·디자인 변경은 GitHub 코드 수정이 필요합니다. DB 속성 이름과 API 연결 권한을 임의로 바꾸지 않습니다.

글이 안 보이면 `공개`, 제목, 현재 또는 과거의 `게시일`을 먼저 확인합니다. 전체 목록에 연결 오류가 나오면 Vercel의 Logs, Production 환경변수, Notion 연결의 두 DB 접근 권한을 확인합니다. 코드 배포 실패는 Vercel Deployments의 Build Logs에서 확인합니다.

## 구현과 검증

- `/notice`: 검색·분류·10건 단위 페이지 이동, 최신순 목록.
- `/research`: PC 4열·태블릿 2열·휴대폰 1열 카드 그리드, 12건 단위 페이지 이동. 최신 게시일 우선이며 같은 게시일에는 제목의 숫자 순서(R1→R2→R3→R4)를 따릅니다. 검색·분류를 유지하며 스크롤 시 카드가 순서대로 나타납니다. 동작 줄이기 설정과 JavaScript 비활성 환경에서도 글을 읽을 수 있습니다.
- 리포트 카드의 표지는 첫 번째 PDF의 첫 페이지입니다. Drive PDF는 서버에서 작은 미리보기 이미지를 가져오며, Notion 업로드 PDF는 화면에 가까워질 때 첫 페이지만 렌더링합니다. 미리보기 생성 지연·공유 제한 등으로 표지가 없더라도 제목을 눌러 글을 열 수 있습니다. 표지는 따로 업로드하지 않아도 됩니다.
- `/notice/[id]`, `/research/[id]`: Notion 본문과 첨부파일. 해당 DB의 공개 글만 접근 가능.
- `/`: 최신 리포트 3건. `/search`: 공개 공지·리포트의 제목·요약·분류·작성자와 기존 사이트 정보 검색.
- 첨부파일은 클릭할 때 API에서 다시 조회하여 만료된 서명 URL을 새로 받습니다.
- `외부 링크`의 Google Drive 파일과 `첨부파일`의 Drive 링크·Notion 업로드 PDF는 사이트 내 PDF.js 뷰어 및 다운로드를 지원합니다. 일반 외부 링크와 기타 첨부파일은 기존 링크로 표시합니다.
- `/api/content/[kind]/[id]/pdf`: 공개 여부와 DB 소속을 매번 확인한 뒤 허용된 파일 호스트에서만 PDF를 스트리밍합니다. 파일 ID나 임의 URL을 방문자가 직접 지정할 수 없습니다. 외부 쿠키·계정 정보·Drive 주소는 전달하지 않으며, 다운로드에는 한글 파일명과 `attachment` 헤더를 제공합니다. Notion 공개 해제 후 새 요청은 404입니다.
- PDF 뷰어·worker·한글 CMap·기본 글꼴은 같은 사이트에서 제공합니다. `predev`와 `prebuild`가 설치된 PDF.js 버전에 맞는 파일을 자동 준비합니다. `public/pdfjs`는 생성물이므로 Git에는 포함하지 않습니다.
- PDF는 메모리에 통째로 저장하지 않고 스트리밍하여 큰 파일을 전달합니다. [Vercel 스트리밍과 응답 크기 안내](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions). 방문자의 PDF 열람·다운로드는 Vercel 데이터 전송량과 함수 사용량에 포함됩니다. Drive 다운로드 제한·공유 해제·일부 대용량 파일의 확인 화면이 발생하면 뷰어에 오류가 표시되므로, 새 파일 게시 후 반드시 확인합니다.
- Notion 요청은 서버에서만 실행하며 `no-store`를 사용합니다. API 실패는 빈 목록과 다른 메시지로 표시하고 상세/파일 요청은 실패 상태를 반환합니다.
- Notion API 버전은 `2025-09-03`으로 고정합니다. [공식 API 자료](https://developers.notion.com/reference/intro), [Next.js fetch 문서](https://nextjs.org/docs/app/api-reference/functions/fetch).
- 본문 지원: 문단, 제목, 글머리/번호 목록, 인용, 콜아웃, 토글, 체크리스트, 표, 열, 코드, 이미지와 파일/외부 자료 링크. 미지원 블록에는 안내 문구가 표시됩니다. 하위 페이지·연결 DB·동기화 블록은 따라가지 않습니다. 중첩 8단계를 초과하면 오류로 처리합니다.

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm start
```

자동 테스트는 모의 Notion 응답을 사용합니다. 2026-10-03에는 실제 학회 Notion API와 로컬 개발 서버로 다음을 추가 확인했습니다.

- 읽기 전용 연결로 두 DB 접근 성공, 연결 범위 밖 DB 접근 불가.
- 공지 공개 시 목록·상세 본문·검색 반영, 리포트 공개 시 목록·상세 본문·홈 최신 리포트·검색 반영.

같은 날 운영 사이트에서도 공개 공지·리포트의 목록·상세·검색 및 홈 최신 리포트 반영을 확인했습니다. 리포트의 `첨부파일`에 임시로 등록한 공개 PDF 링크는 사이트의 첨부 경로를 거쳐 HTTP 200과 PDF 데이터로 응답했습니다. 확인 후 두 예시의 공개·게시일·임시 첨부를 원상 복구하고, 사이트에서 숨김 및 상세·첨부 경로 404를 확인했습니다.

PDF 검증은 외부 PDF를 `첨부파일`에 링크로 등록한 방식입니다. Notion에 직접 업로드한 학회 PDF와 서명 URL 만료 후 재열기는 아직 실물 검증하지 않았습니다. 원본의 큰 이미지 파일은 보존되어 있으므로 운영 트래픽이 많아지면 이미지 최적화를 별도로 진행할 수 있습니다.
